# Whole clientAudio helper versus AIL boundary bridge

Read-only inspection of current source. Neither boundary currently proves the user's complete original experience. Moving more code into32-bit process removes some callbacks from IPC but also moves game policy, state and engine dependencies across it; it is not simply moving Audio.cpp unchanged.

## Concrete closure and data contract

- Audio.cpp:87–130 owns maps keyed by CrcString pointers, SoundId→Sound2 pointers, SampleId→Miles handles, UINTa→AbstractFile pointers, listener ConstWatcher<Object>, sample caches, priority lists and provider/device globals. These cannot be serialized as addresses. Handles need process-local ownership plus explicit lifetime/generation IDs.
- Audio::alter:1931 receives real Object listener and reads world position/forward/up:1956–1959. Sound2::getPosition_w:241 reads Object/Appearance lifetime, asynchronous loaded state, named hardpoint transform and object→world transform. Sound2.h owns watcher and CellProperty pointers; attachment/deletion, cells and hardpoints require updates at their original observation boundaries, not just a once-per-frame position packet. Public Audio.h also exposes Object-based detach/ownership-transfer, Iff input and listener getters. Host-side Object/Appearance duplication is substantial engine-state mirroring, not a transparent transport.
- Sound2d.cpp:145,482,544,1002–1183 uses shared Random for loops, pitch, volume, delay and fades. Moving these draws into an independently seeded helper changes global RNG consumption and potentially game-visible later draws. Replay/synchronous RNG service or a deliberate game-policy refactor is required; a matching seed alone is insufficient.
- Miles file callbacks Audio.cpp:3947+ use TreeFile::open and real AbstractFile seek/read/close; compressed sample cache uses TreeFile at1554/3703. A helper needs identical virtual mount/patch precedence and bytes, or an explicit file-service boundary with synchronous reads. Raw OS pathname access is not equivalent. Sound templates also need genuine Iff/template/config/table loading, not a synthetic sample-only substitute.
- Sound2d::endOfSample:845 sets end flag, increments loop, invokes arbitrary game callback then resets fade/time. Comment explicitly defers certain Miles operations until alter. Whole-subsystem hosting keeps this mutation beside Miles, but still has to invoke game callback across processes with original ordering/reentrancy restrictions. AIL hosting keeps these mutations in x64 but must deliver EOS without frame batching; both retain an unavoidable process-boundary timing question.
- Audio::alter is also invoked synchronously outside normal game frame: stopAllSounds:3770 and PlayerMusicManager.cpp:162/181/216/236. A once-per-frame event model is already incompatible with these source call sites.
- BinkVideo.cpp:117 passes the actual Miles digital driver to BinkSoundUseMiles. Preserving this means original Bink and Miles share the32-bit owner process/device. Sending the driver address to64-bit code cannot work. Decoded Bink image transfer/presentation remains another boundary, regardless of where Sound2d lives.

## Rival consequences

**Whole clientAudio/Sound2d/Sound3d host:** fewer low-level AIL round trips and EOS policy stays on its native Miles thread. But game-facing Audio is not a value-only API: object/watchers/cells/Iff/callbacks/shared RNG and synchronous query results are embedded. Full unchanged subsystem cannot just be transplanted. A workable variant needs a deliberate value-state facade, strict update ordering and game lifetime/RNG services. Reject as the “small transparent move” unless that facade and reference trace are demonstrated. No reason from source to claim it preserves timing better overall before measurement.

**AIL boundary with x64 audio policy:** leaves genuine game Object/TreeFile/Random/template/prioritization code where it already runs; process IDs replace Miles pointers and buffers/file callbacks require transport. Smaller game-state semantic surface, but many fine-grained synchronous calls and EOS reentrancy/file callbacks can create delay or deadlock. Unsolicited callbacks have measured delay; queuing to next frame was already wrong. Reject any version that substitutes asynchronous cached query results, frame-batches callbacks, holds request locks while awaiting callbacks, or moves Bink to a separate audio device. A fully serviced AIL protocol is not proven by one sample-start command.

## Smallest decision-making real-engine slice

Start with a genuine Sound2d template containing two sequential samples/finite loop, original engine Audio/Sound2d state machine, original Random and TreeFile bytes, on the same actual Miles+Bink device owner. Compare a Win32 in-process reference with each proposed boundary for play→EOS→next alter/loop→stop and immediate time/status queries. Add one caller EOS callback that makes only a source-permitted Audio query, and one explicit alter(0) outside the frame. Record sample-selection/RNG draws, sound/sample IDs, callback/thread/order, bytes handed to Miles, file seek/read order, onset/EOS and captured PCM. Fixed measured scheduling differences remain differences; no inferred tolerance. For whole-subsystem version, this initial unparented2D slice deliberately omits Object/cell/3D/hardpoint paths and cannot establish full integration; next discriminator must include deletion of a real attached sound owner and a moving hardpoint. AIL version must implement all actual calls exercised; no stand-ins for unimplemented API to make the full client link.

Decision: AIL boundary is the narrower initial fidelity experiment because it retains game policy and shared-state observation in the x64 process. Whole-subsystem hosting remains a genuine alternative, but only if its state facade is acknowledged as new integration work rather than described as unchanged engine behavior. Neither warrants production selection or a100%fidelity claim today.
