# Architecture opening — the smallest coherent media boundary

2026-09-30. Independent architecture/design follow-up; nonblind to my preceding component/source reviews and the parent's task framing. I did not read the parent's new design. Source reviewed at `/home/akilleez/Work/swg-source/client-build-next`, HEAD `49d0eeed4ddaa177d7a93ea396c37c3d9b9942da`. No execution, product changes, or new agents. This document is a proposal, not an implementation or fidelity certificate.

**Recommendation:** Build one deliberately narrow **MediaSession** between the x64 game and an x86 host containing the original Miles and Bink. Keep Audio/Sound2d, game callbacks, TreeFile ownership, object relationships, random choices and graphics presentation in x64. Give one coordinator responsibility for resource lifetime, call completion, reverse file operations, callback completion and closing. The codec, registry, scalar dispatcher and retained-buffer store belong behind that coordinator; their preconditions are its work, not proof that the work already exists.

The architectural simplification is a single ownership/lifecycle contract, not a smaller number of function names. Do not create a general RPC platform or implement the whole Miles SDK. Do not split Bink audio from its original Miles driver merely to make isolated demos easier.

## Why this boundary, from the source

Here **A** means `src/engine/client/library/clientAudio/src/win32/Audio.cpp`; neighboring Sound2/Sound2d paths are abbreviated similarly. Bink paths are under `src/engine/client/library/clientGraphics/src/Bink/`.

- `Audio::alter` reads the listener's position/orientation and runs sound policy (`A:1931,1953–1962,2019`). Sound2 resolves live Object appearance hardpoints/transforms and parent cells (`Sound2.cpp:186–194,240–299`). Sound2d checks object death and decides fades/occlusion/volume/playback rate (`Sound2d.cpp:330,349–455`). These belong with the game world.
- Sound2d consumes shared `Random` for loop count, pitch, volume and delays (`145,482,544,1002–1018`), **and CRT `rand()`** for play order (`961–968`). `sharedRandom/src/shared/Random.cpp:18,28–34` holds a shared generator. Moving sound policy changes cross-subsystem random consumption unless the original request sequence is preserved; merely giving the host the same seed is insufficient.
- EOS changes Sound2d loop/timer state (`845–873`). The actual registered game callback in `clientGame/src/shared/scene/PlayerMusicManager.cpp:103–106` sets a game flag and starts a timer; registration occurs at `177,231`. Delaying that callback can alter player-music timing even if the same sample is eventually audible.
- `ClientMain.cpp:314` gives Bink the Miles driver through VideoList; `BinkVideo.cpp:100–117` uses it. Vendor driver and Bink sound backend therefore remain in one address space. Bink's decoded metadata/frame buffers cross the boundary; original HBINK structures and driver pointers do not.
- Virtual IO must retain the game's TreeFile policy. Miles callbacks use TreeFile/AbstractFile (`A:3939–4098`); Bink's local IO helpers cast native file handles to AbstractFile pointers (`BinkTreeFileIO.cpp:29–68`). Those casts cannot survive a process boundary unchanged. Keep Bink's buffering/decode logic with Bink, replace only its leaf file access with a reverse file service.

| Alternative | Judgment |
|---|---|
| Transparent forwarding of every Miles export | Too broad. It exposes vendor ABI and arbitrary pointer semantics as the architecture, while omitting Bink and lifecycle coordination. |
| Forward only the 61 reachable Miles calls | Useful implementation inventory and comparison oracle. Still incomplete as a boundary: callbacks, buffer retention, driver sharing and session failure are not ordinary scalar calls. |
| Host all clientAudio | Fewer apparent Miles crossings, but requires world/object proxies, sound-template/game callback transport, RNG-order preservation and duplicated engine/file bootstrap. That is a larger semantic boundary under the x64-policy requirement. |
| x64 policy + typed media resources + original x86 Miles/Bink | Smallest coherent ownership cut supported by the inspected source. It still has to pass the scheduling and real-engine gate below. |

## Shape of the implementation

Use three pieces: a small x64 adapter at the existing vendor seam; one MediaSession coordinator; and a thin x86 vendor owner. The adapter must preserve the original statement order, return values and output-mask/null distinctions. Internal dispatch can retain the existing opcode table. Avoid public fake Miles exports: source-visible typed wrappers make resource ownership explicit and allow the original direct Win32 path to remain the comparison implementation.

The domain objects are session/driver, owned sample, stream with its borrowed sample alias, retained byte image, virtual file, and video/frame. Each request names a typed operation on one of those objects. Do not replace several original calls with a synthetic “play sound” operation that silently reorders setter, callback-registration, start or failure behavior. Optimizing transport is a later measurement-driven step. Existing 61-call coverage remains a requirement checklist, not a promise to preserve unused SDK entry points.

Start with one local reliable ordered connection, bounded control messages and explicit payload transfers. It carries ordinary requests/replies, reverse file requests/replies, and callback notifications/acknowledgements. A receive path must keep making progress while a request waits. No network discovery, distributed services, plugin dispatch, arbitrary remote function invocation or transparent automatic retry is needed. Video payloads should use a separately owned bounded frame buffer/ring rather than occupy the control stream long enough to block reverse file reads; the exact copy/shared-mapping choice is a performance decision, not part of game policy.

## Coordinator contracts

**Session and driver.** Session has a fresh incarnation identity and states Starting → Running → Draining → Closed, with Faulted terminal for this incarnation. Handshake verifies the actual intended DLL set and protocol, then host initializes Miles and opens the original driver. Bink receives that real driver only after it is live. No returned token is a native pointer. Any token or message from an old incarnation rejects before vendor dispatch. Driver teardown follows its dependency graph: complete/close videos and their IO first, quiesce samples/streams/callbacks next, then original vendor shutdown. Match source teardown semantics rather than assume adding a second driver-close is harmless.

**Resources and bytes.** Host owns every vendor handle and every byte address passed to vendor code. x64 owns SoundId/game policy and TreeFile objects. Handles contain kind, slot, generation and session binding; borrowed samples reference their parent stream and cannot be independently released. Buffer images are immutable, sized and explicitly associated with users. Stage an image before calling the vendor; retain the old and attempted images until the actual vendor reference contract permits retirement. Neither failure nor successful replacement proves release by itself. Close invalidates public admission first, waits for the relevant vendor/callback references, then retires buffers and identities. No “timeout means free it” rule.

**Request completion.** Each admitted request has a unique request ID and logical lane; replies match that ID and carry a transport outcome separately from the exact vendor result. Within one calling lane, keep the original order and synchronous visibility. State queries execute as queries, not cached approximations. “Not admitted” is distinguishable from “vendor may have executed but reply was lost.” Never retry start, seek, release or registration on an ambiguous outcome. Initially permit no pipelining of dependent calls. Keep enough causal identity for reverse calls without building a general dependency scheduler.

**File reverse calls.** Four typed operations—open, seek, read, close—suffice for the common leaf service, with explicit differences in Miles/Bink return conventions handled at their adapters. x64 file tokens map to real AbstractFile objects; per-file operations preserve the vendor's order and returned counts/positions. Bytes are copied to the vendor's local destination only after a matching read reply. No filename substitution or direct host filesystem shortcut for TreeFile assets. A file callback originating synchronously inside a game request should be serviced on that waiting x64 caller where feasible; callbacks originating on vendor workers require a known x64 callback/file lane with engine thread setup. Routing must be explicit because Audio::serve checks main-thread identity (`A:4943–4958`).

**Callback completion and scheduling.** Unsolicited EOS needs its own progress path; it must not wait for the next audio API call or Audio::serve. The host trampoline captures resource generation, registration identity, event sequence and origin lane while the native handle is live. x64 resolves the corresponding local proxy, invokes the existing callback body exactly once for that registration, then acknowledges completion. An acknowledgement distinguishes “bytes received” from “game callback finished,” which matters for close. Delivering callbacks immediately on a dedicated x64 callback lane is a **candidate**, not an established equivalent of the original vendor worker. Do not arbitrarily batch callbacks at frame boundaries.

The original callback is synchronous with its invoking vendor frame. Therefore a host trampoline should normally remain live until the x64 callback acknowledgement, rather than returning early and pretending invocation completed. Whether such waiting is safe under the original driver's locks must be measured. The currently inspected EOS body and PlayerMusic callback do not call Miles directly; do not implement unrestricted recursive RPC just in case. Inventory any reachable nested call before admitting it. If a real synchronous reverse callback can cause a nested vendor call, dispatch that causal descendant on the original waiting host lane if vendor reentrancy permits it; never queue it behind its blocked ancestor. If this requires broad arbitrary reentrancy, reconsider the boundary before expanding the framework.

**Lock scope.** The existing `Audio::lock` covers a batch of starts (`A:2320–2337`), not merely each individual request. Represent it as a lease held by one logical x64 caller, executed on the same host thread from lock through unlock. Other unrelated caller requests cannot enter that lease. Reverse replies and required callback traffic must still flow; never hold a connection/registry mutex while waiting for them. The lease does not mean “suspend the x64 main thread on all callbacks.” The header defaults and later reported measurements do not support that universal assumption. Preserve the actual original vendor lock and mutex behavior within the host, then measure the added x64 callback admission policy.

**Failure and recovery.** Distinguish a normal vendor failure from transport failure. Normal vendor failure returns the original result and retains resources according to its real contract. Transport/process loss faults the whole media incarnation, wakes blocked callers and prevents additional dispatch through old handles. It cannot be disguised as EOS, success, ordinary silence or a null-return fallback. Do not claim transparent recovery: host mixer phase, file cursors and already-executed commands are not generally reconstructible from a last reply. Keep the failure visible; a fresh client/session restart is the minimum honest recovery until stronger restoration is demonstrated. In-flight data should not be reclaimed as though callbacks had completed; host process death ends its address-space references, while x64 callback/file obligations still need local cancellation/joining.

**Bink frames.** Keep original decode/wait/advance/pause/seek semantics and sound output in the host. x64 retains texture creation, device-loss callbacks and rendering. Replace direct `m_video->Width/Height/FrameNum` reads (`BinkVideo.cpp:442,449,470,502–504`) with metadata returned at the same logical observation points; do not invent a locally advancing playhead. A frame carries video generation, frame index, format, extent/stride and a buffer lease released after upload/use. Seek/close invalidates queued frames of the prior generation. Do not introduce extra dropping or repeat-frame policy beyond the original source to mask transfer latency.

## Counterexample schedules the design must survive

1. **Reverse-call deadlock:** game waits for OpenStream; host enters vendor open; vendor requests TreeFile read; x64 cannot service it because its only loop is waiting for the open reply. Independent receive progress plus servicing the reverse operation on the admitted caller/lane breaks this cycle. A second thread that merely receives bytes is insufficient if it cannot execute the callback.
2. **Nested ancestor deadlock:** host callback waits for a reverse-file reply; that x64 execution reaches a permitted nested audio operation; ordinary host queue puts it behind the still-running original request. Causal dispatch on the correct waiting host lane is required if this path is reachable. Source only proves an audio-service hook in `AbstractFile::readEntireFileAndClose` (`fileInterface/src/shared/AbstractFile.cpp:52–55`) and registration at `A:1366`; it does **not** prove every low-level vendor read invokes that hook. Trace reachability before adding a nested scheduler.
3. **Late EOS hits replacement:** EOS for sample generation A is queued; x64 closes/reuses the slot for B; transport delivers A. Resource generation plus callback-registration identity must prevent calling B's callback. A teardown fence must ensure events that the original contract requires are completed before returning close; indiscriminately dropping all pending EOS is not a fidelity proof.
4. **Polling changes music:** EOS occurs during a game frame with no subsequent vendor call; bridge waits until the next serve to deliver it. Sound2d's next alter sees a different `m_endOfSample`, and PlayerMusic's timer begins later. A push callback path removes the artificial serve dependency, but latency/order still need comparison.
5. **Lock owner starvation:** x64 holds the remote AIL lock, another request is at the queue head, and the owner's next setter/unlock sits behind it while the host waits for ownership. Admission must select the lease owner's continuation without admitting unrelated vendor work; reverse replies cannot be trapped behind the same queue.
6. **Reply lost after start:** host starts the sample then dies or disconnects before replying. Retrying starts twice or restarts elapsed playback; returning false claims a vendor result never observed. Classify the session as failed with execution outcome unknown.
7. **Stale video transfer:** frame N arrives after seek/close or a replacement video reuses its slot. Frame/video generation and lease ownership reject it without releasing storage still being uploaded. A Miles-only resource registry cannot supply this contract automatically.

## Unsupported assumptions and the decisive next gate

This design assumes the reachable callback/body inventory is narrow enough to preserve without hosting game policy, that lane/lease routing can preserve relevant ordering, that host-held callback acknowledgements do not deadlock the genuine DLL, and that frame/IO transfer cost fits original behavior. It assumes original Miles/Bink binaries can operate together in the proposed helper and that their actual valid-output pointer/lifetime contracts can be represented. None is established by a codec, token registry, compile pass, scalar probe or a single valid WAV query. FPU/exception state belongs to each actual host dispatch/callback context and must be observed, not globally normalized speculatively.

The next gate is one **real engine comparison**, not assembly of every wrapper first. Establish the original Win32 baseline through clean teardown. Then run the same x64 Audio/Sound2d policy through a minimal MediaSession with an owned sample and a TreeFile stream: actual startup/driver, retained bytes, borrowed-sample volume/rate, original start lock scope, reverse IO, asynchronous EOS, close and teardown. Use object motion/destruction and deterministic sound-choice inputs to compare policy decisions and random consumption, and include the registered game callback's timer observation. Record causal/lane/lease trace plus engine state, callback timing and output evidence. Add a short Bink clip sharing that actual driver before approving the boundary for full implementation; a separate silent video demo is insufficient.

A failure should identify which contract failed, rather than trigger an expanding generic IPC framework or moved game policy. Coalescing calls, batching frame updates, caching queries or reconnecting automatically require their own evidence later. This design minimizes the semantic cut and keeps original implementations where available. It does not and cannot turn finite observations into a universal 100% fidelity guarantee; the original feature and behavior requirements remain the acceptance target, with measured coverage stated explicitly.
