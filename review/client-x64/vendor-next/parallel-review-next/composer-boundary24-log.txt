## 1. Public boundary vs wire/process (game-facing)

**Satisfied (within excerpts)**  
- `ClientMiles.h` exposes only Miles-shaped startup helpers, `OwnedText`, `Failure`/`FailureReason`, and opaque `HDIGDRIVER`. No opcodes, handles, frames, Hello/SessionClose, pipes, or child-process types (`ClientMiles.h` 8–69).  
- `sample/startup_calls.cpp` includes only `startup_calls.h` → `ClientMiles.h` (lines 1–25).  
- Deletion/isolation tree allows only `ClientMiles.h`, sample headers/sources, `link_double.cpp`, `link_main.cpp` (`check-portable.py` 59–67); dependency scan requires deps stay in that set (79–84).

**Advisory — composition root not on the public facade**  
- Pipe implementations call `ClientMilesPipe::Session::selected()` from every `ClientMiles::*` entry (`ClientMilesPipe.cpp` 143–145, 154–156, etc.). Selection is via `Session` construction (`Session.h` 14–15, `ClientMilesPipe.cpp` 70–75), which lives under `pipe/`, not in `ClientMiles.h`.  
- **Counterexample:** Game TU includes only `ClientMiles.h` and links `ClientMilesPipe.cpp` without ever constructing `Session`.  
- **Impact:** Every call throws `Failure(WrongState, "Miles implementation not selected")` (`ClientMilesPipe.cpp` 85–88). Not a wire leak; it is an undocumented-at-API-level wiring requirement (header comment 8–9 vs no public selector).

**Advisory — opaque driver is still implementation-coupled when pipe-linked**  
- `DigitalDriver` stores `MilesWire::Handle` and `Session*` (`ClientMilesPipe.cpp` 6–9). Public header only forward-declares `DigitalDriver` (`ClientMiles.h` 11–12). Game code cannot see wire fields without violating layering; identity checks in `speaker_configuration_spec` bind handles to the active session (`ClientMilesPipe.cpp` 230–235). Expected for pipe backend; not an escape into game policy if include discipline holds.

Sample uses `"miles"` without slash (`startup_calls.cpp` 7). **Not a sample/adapter mismatch**—oracle is host-returned text; sample args still send `"miles"` (adapter_test directory step 121–122).

## 5. Native compile-only candidate vs “Miles-shaped at build time”

**Limitation**  
- `native_miles64.cpp` is gated to `_WIN64` + `_MSC_VER == 1800` (8–10); not built by `check-portable.py` (g++ adapter test only, 43–56).  
- `static_assert` signature parity covers only `startup`, `shutdown`, `get_preference`, `set_preference` (21–30), not `open_digital_driver`, `last_error`, redist, `MSS_version`, or `speaker_configuration_spec`.  
- **Impact:** “Ordinary Miles-shaped” is **partially** evidenced at compile time; other entry points rely on manual implementation match (e.g. `speaker_configuration_spec` vs five-argument SDK, 96–99).

**Behavioral split (documented)**  
- Native `open_digital_driver` / `get_preference` / `set_preference` have **no** pipe subset guards (`native_miles64.cpp` 63–68, 91–93). Same `ClientMiles.h` API, different rejection rules per linked TU—by design if build selects pipe vs native.

**Advisory — `MSS_versionOwned` semantics**  
- Native: fill 256-byte buffer, throw `QueryFailed` if no NUL/content (82–88).  
- Pipe: `SessionVersion` opcode (`ClientMilesPipe.cpp` 203–206).  
- Windows macro `AIL_MSS_version` loads DLL resource (`user` minimal header note)—native path is not a plain function delegate like `AIL_startup`. Compile-only file includes `<Mss.h>` and calls `AIL_MSS_version` (85)—consistency with macro expansion not shown in excerpts.

**Advisory — redist lifetime**  
- Native retains path strings until `shutdown()` (`native_miles64.cpp` 40, 58–60, 75–79).  
- Pipe sends bytes per call (`ClientMilesPipe.cpp` 191–200); no client-side retention list in excerpt. Owned text is copied from replies (`ownedText`, 50–61). Adequate if host owns vendor pointers; differs from native retention model.

## 7. Concrete defect candidates (bugs vs limits)

### 7.1 `shutdown()` unavailable after `startup()` returned 0 (pipe)

- **Where:** `startup()` sets `session.started = (value != 0)` (`ClientMilesPipe.cpp` 149–151); `shutdown()` calls `requireRunning()` → needs `started` (`154–157`, 98–101).  
- **Counterexample:** Vendor/pipe returns `0` from `AIL_startup`; caller wishes to call `shutdown()` to match SDK pairing.  
- **Impact:** `WrongState` throw. Sample avoids by early return (`startup_calls.cpp` 9–10). SDK `AIL_shutdown` after failed startup not represented in excerpts; may or may not be valid for Miles—**facade forbids the call**.

Classify as **facade lifecycle bug** if policy requires symmetric teardown after zero startup; otherwise **documented strict state machine**.

### 7.2 Faulted session: no recovery path

- **Where:** Transport/unknown status sets `faulted_` (`ClientMilesPipe.cpp` 112–118, 106–108); subsequent ops throw `BackendFailed`; `shutdown()` and `close()` also blocked (`126–128`, 231–232 in tests).  
- **Impact:** Composition root must destroy `Session`/channel without `close()` succeeding (`Session.cpp` 78–80 comment). Limitation if intentional; operational hazard if game expects retry.

Tests encode this as intended (`terminalFailures`, 212–251).

### 7.3 `set_preference` error message conflates distinct rejections

- **Where:** One message for wrong ID, wrong value, and intptr_t overflow (`ClientMilesPipe.cpp` 175–178).  
- **Impact:** Diagnostics only; behavior correct (`InvalidArgument`).

Minor; not a functional bug.
