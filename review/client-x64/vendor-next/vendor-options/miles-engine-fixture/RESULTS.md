# Genuine Win32 Audio/Sound2d fixture: playback observed, teardown unresolved

2026-09-30. **Not a passing end-to-end integration test.** Actual engine playback
completed, but foundation/ExitChain teardown raises an access violation. No
backend adapter, production edit, fake export, codec replacement or game startup.

## Native build and actual closure

The native v120 Win32 Release fixture compiled and linked with exit 0 against
current integration `49d0eeed4ddaa177d7a93ea396c37c3d9b9942da` genuine Win32 libraries
in `C:/integration-current-v2/workspace/repo`. No R/Q mapping or source mutation.
Compile definitions/include paths came from actual clientAudio CL tlog; link
library paths/dependencies came from the completed product Release link command.
The fixture did not reuse the product entry object, resources, or /FORCE.

The map explicitly contains `clientAudio:Audio.obj`, `Sound2d.obj`,
`Sound2dTemplate.obj`, `SetupClientAudio.obj` and real dependency implementations.
The resulting PE imports **54 actual AIL exports** from mss32.dll, plus Windows
system DLLs. Thus the single runtime route has a broader linked dependency
closure. `imports.txt`/`summary.json` record the exact list; no substitute Miles
functions were provided. `native-evidence.zip` contains compile/link commands,
logs, maps and real input hashes. The linker dependency extraction also included
the product import-library argument; no SwgClient provider appears in the map or
PE imports. This unused input should be removed when packaging the fixture.

## Actual exercised route

SetupSharedThread/Debug/Foundation/File/Math/Utility/Random and SetupClientAudio
are real implementations. The fixture creates a real Sound2dTemplate with its
public setters, two distinct sample paths and finite count two, writes it through
actual Iff, then loads/plays it through `Audio::playSound("probe.snd")`.
The template is deterministic fixture data generated by the actual serializer,
not an existing retail `.snd` or copied state machine. Both private paths use the
same existing 204 ms WAV bytes; this distinguishes engine sample lifetimes, not
codec/music differences. Actual TreeFile/cache and original Miles are used.

The public completion callback is invoked by real Audio/Sound2d code. The fixture
calls real Audio::alter/serve, queries real Audio::getCurrentSoundTime and
getSoundById, observes real SampleIds, and includes both initial alter(0) and a
second alter(0) at epoch 40. No private state is fabricated or rewritten.

## Exact unresolved teardown evidence

At v3: `c0000005`, instruction `00421494`, image base `00400000`, inside the
mapped real `MemoryManager::free` implementation. Disassembly shows a read of
`[eax+8]` while examining the previous block in free/coalescing. That is a fault
location, **not proof the allocator caused the bad state**. The short captured
stack does not identify the owning ExitChain callback or allocation. No safe
claim yet distinguishes an incomplete fixture setup/lifetime contract, a library
ABI issue, or a pre-existing engine cleanup defect.

Do not call this a green baseline, suppress teardown, substitute frees, or add
another deliberately failing allocator workload. Next diagnosis should inspect
actual cleanup/lifetime ordering and use source/symbol evidence to identify the
free's caller before deciding on a repair. Fixture-local SoundId lifetime also
needs review against shutdown ordering; it currently outlives the call to
SetupSharedFoundation::remove. No causal conclusion is drawn from that alone.
