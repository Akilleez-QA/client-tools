## Strong findings first

1. **Logitech LCD is a real startup path**, not an unused named library: ClientMain.cpp:361 calls initializeLcd; SwgCuiG15Lcd.cpp:29 defines USE_LCD, :323 checks the configuration, then :334 creates CEzLcd and calls InitYourself. ConfigClientUserInterface.cpp:248 defaults disableG15Lcd=false. LCDOutput.cpp:15 has a real lgLcd.lib autolink and :95 calls lgLcdInit. The UI implementation source exists; the low-level library is pe-i386. A missing physical LCD/manager is already handled by remove/return, but that does **not** authorize removing support from x64.
2. **TCG wrapper setup does not load the TCG engine.** SwgCuiManager.cpp:475 calls install; SwgCuiTcgManager.cpp:49–80 registers directory/realm/desktop and audio/navigation callbacks. libEverQuestTCG.cpp:199 init only records settings. launch (:355) creates Manager; Manager::init (:433–480) loads SWGTCG.dll and binds exports. The normal HUD launch lines at SwgCuiHudAction.cpp:1617–1618 are commented. The source search found no other first-party launch invocation outside the manager itself. Treat functionality reachability as currently limited/unresolved, not universally live and not safe to delete.
3. **The browser is also conditionally suppressed in current source.** SwgCuiWebBrowserManager install/update and SwgCuiWebBrowserWidget.cpp:28,41 are under unusual `#if DEBUG=0` guards. Do not reinterpret this as a proper `DEBUG == 0` check. Native macro/preprocessor state must settle each configuration. Wrapper presence alone does not establish startup loading. The repository browser SDK identifies Mozilla **1.8.0.9** (mozilla-config.h:19) and NSPR **4.6.1** (prinit.h:66); only one wrapper .cpp is present, not the browser engine.
4. **Capture differs between configurations.** SwgVideoCapture.cpp:17 and CuiIoWin.cpp:208 are guarded `PRODUCTION == 0`; Production.h:13–16 derives that from DEBUG_LEVEL. Game.cpp:3016ff capture configuration/start/stop entry points are literal `#if 0`. Thus Debug contains a per-draw `SingleUse::run()` reference while normal Release excludes this body. Do not call all capture libraries a Release runtime prerequisite, and do not remove them from Debug merely because launch commands are disabled.

They must not be relabeled missing proprietary SDKs because the executable lists old archive names. Remaining MFC/ATL debug libraries in Release, unicows, duplicate libxml/vivox/capture names and Xbox Deja are **stale candidates**, not proven runtime features. Full x64 client link has not yet furnished an authoritative complete imported/extracted list.

Observed local packaged SwgClient_r.exe imports only DINPUT8, DPVS, Miles and Windows libraries in its PE import table. That is a **different packaged binary**, not proof about current source-head executables; dynamically loaded Bink/Vivox/TCG are not ruled out. Preserve exact native product-head module and linker traces as the next authority.

## Research log and explicit limits (checked 2026-09-30)

- Mozilla [NSPR build instructions](https://firefox-source-docs.mozilla.org/nspr/nspr_build_instructions.html) describe native Windows64 builds; [NSPR4.6.1 release](https://www-archive.mozilla.org/projects/nspr/release-notes/nspr461) supplies historical version context. Neither proves XUL1.8.0.9/SOE-patch x64 availability. Official XULRunner archive directory fetch failed in this pass; exact source provenance unresolved.
- [Mozilla current embedding architecture](https://firefox-source-docs.mozilla.org/dom/navigation/embedding.html) documents current in-process/remote embedding; it is not a compatible substitute for the old internal API.
- [Logitech current developer lab](https://www.logitechg.com/en-us/programs/partner-developer-lab) lists wheel/LED SDKs and runtime software requirements. Search for official historical LCD SDK did not establish current compatible x64 availability; third-party mirrors were not treated as authoritative distributions.
- [Accusoft PICTools Photo](https://www.accusoft.com/products/sdks/pictools-photo/) lists32/64 Windows. [Opcode/license matrix](https://help.accusoft.com/PICTools/ProgrammersReference/OpcodeMatrix-PICTools.html) treats platform SDK variants separately. Current availability is not legacy compatibility or possession of the needed package.
- [NVIDIA Cg FAQ](https://developer.nvidia.com/cg-faq) says3.1 is the final legacy release, not actively supported; [archive](https://developer.nvidia.com/cg-toolkit-archive) covers legacy distribution. - Primary Daybreak search did not establish an operational SWGTCG service or current compatible SDK. No live account/service test performed; report **unverified**, not a fabricated availability conclusion.
