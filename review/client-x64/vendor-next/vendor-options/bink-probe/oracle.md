# Prediction and fixed oracle (written before decoding)
Expected: the original PE32 runtime can decode an original Bink movie in a v120 x86 console process; an x64 process can launch it and receive bounded framed bytes. Neither proves integrated x64 playback or experience equivalence.
Select the smallest positive-size original .bik from bounded TRE metadata. Decode sequential frames 1 through 32; retain samples 1, 8, 16, 32 (or available subset). Original output is BINKSURFACE32A | BINKCOPYALL, positive width*4 pitch, top-down BGRA, buffer initially zero. Compare SHA-256 including alpha, and separately RGB/alpha differences against installed FFmpeg BGRA with explicitly selected BT.601 limited-range YUV to full-range RGB, bilinear conversion. Do not alter conversion after results. Bink's internal conversion is opaque; mismatches remain mismatches. Hash equality only establishes equality of these bytes for these samples.
Audio: if exported track API and header MaxSize permit, open track index 0, allocate exactly MaxSize (<=4 MiB), extract once per decoded frame and hash returned bytes. No sound device or playback, no A/V fidelity claim, no timing/seek/loop/input/device-loss/language/multitrack acceptance.
Limits: <=256 TREs, <=32 MiB per metadata block, <=256 MiB cumulative metadata reads, <=64 MiB selected movie, dimensions <=1920x1080, <=32 decoded frames, <=4 retained frames, <=256 MiB probe-generated disk data per host, <=60 seconds per decode process, <=120 seconds per build. Local-only private artifacts; no upload/public output. Abort unsupported compression/invalid sizes, do not guess formats.
