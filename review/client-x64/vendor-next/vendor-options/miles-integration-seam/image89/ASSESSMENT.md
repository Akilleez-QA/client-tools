# Image89: actual extents and ownership before four missing exports

Source-only; no code/candidate/product mutation, runtime, compiler, Git or allocator experiment. Public70 signatures remain fixed. Scope is actual Audio/SampleCache and previously authored upload/metadata/binding evidence, not inference that a synchronous setter copies its input.

## Concrete caller map

Product paths below are under src/engine/client/library/clientAudio/src/win32/.

- Audio.cpp:2534–2546 getSampleType(fileImage,fileSize) checks nonnull/positive size and calls AIL_file_type with explicit count. The native-shaped public file_type already carries that count; an adapter can copy exactly those accessible bytes, never derive an extent by parsing.
- :2825–2836 2D start looks up SampleCacheEntry and supplies m_sampleRawData, m_fileSize, extension and block0 to set_named_sample_file. The extension is an inline five-byte cache field (SampleCacheEntry.h), not an owned wire pointer.
- :2918–2925 3D start retrieves the same cache image but calls set_sample_file with no length. m_fileSize is available in that exact entry although absent from the SDK/public signature. Sample3d also records a size at setPath, but the authoritative allocation extent should come from its cache owner, not a potentially stale independent scalar.
- :3692–3730 getSampleInformation reads an entire temporary file, records fileSize before readEntireFileAndClose, calls WAV_info(image,&info), projects scalars, optionally queries duration/type, then delete[]s image. This image is not in s_sampleCache; a cache-only reverse lookup cannot cover it. The existing code does not explicitly check readEntireFileAndClose result before WAV_info; do not silently invent successful metadata or read an unknown/null allocation while transporting it.
- :4430–4455 getSampleTime takes explicit image+fileSize, binds a temporary sample with set_named_sample_file, queries time, ends and releases only in the success branch. It creates a local SampleCacheEntry for extension formatting, not a new cache-owned allocation. Failed bind's temporary sample is not released by that branch; the adapter must not invent compensating release or manufacture success to hide this caller behavior.
- :5326–5358 playBufferedSound/playBufferedMusic accept external buffer+bufferLength+extension. They reuse persistent sample handles: stop/end an earlier binding, bind new bytes, start, and ignore setter status. stopBuffered*:5368–5384 stops/ends but does not release the sample. These are not s_sampleCache buffers. Find and preserve the real external owner for any eventual adoption; the explicit count solves transport extent, not native retention or replacement.

## Actual cache lifetime

SampleCacheEntry.h contains raw byte pointer, int size/time/refcount and inline extension. Audio.cpp:1509–1530 cacheSample obtains file->length() and readEntireFileAndClose; importantly getSampleTime runs BEFORE the image is assigned into the cache entry. A root resolver that only scans cache cannot service that early helper call, although its named setter already receives size.

Sample2d.cpp:50–75, Sample3d.cpp:53–79 and SampleStream.cpp:50–75 decrease/increase Audio path references on destruction or path replacement. Audio.cpp:347–372 deletes image and path and erases the entry when count reaches zero. releaseSampleId:3378–3412 stops/ends, calls native sample release, clears handle and erases the sample row; row destruction then drops its path reference. This is caller-owned lifetime ordering, not a general SDK proof that all providers stopped touching every bound image. Ordinary end alone leaves a live/reusable sample.

Audio::remove stops/clears maps then calls AIL_shutdown:1437 before its remaining cache image deletion loop:1452–1465. Thus cache ownership can disappear during normal sample-row retirement, while some cache entries survive to shutdown. Do not replace these different boundaries with a blanket end/return-time free rule. Pinning client cache bytes until copy and retaining independent helper bytes after copy are separate obligations.

## Existing work that should be reused

buffer-upload-candidate/buffer_upload.h/.cpp provides bounded declared-size assembly, sequential append, complete seal, and independent copySealed. It has no vendor borrowing; caller must supply session ownership/aggregate budget. RESULTS.md records29 checks under portable sanitizers and native Win32/x64 with a premature-seal mutant. It explicitly did NOT test real wire upload handlers. Source implementation reviewed here; historical execution is reported evidence, not rerun89. Existing protocol Buffer handles/BufferBegin/Chunk/Seal/Release can host the ownership transfer rather than a new generic image registry. Actual86 does not select this component or those handlers.

transport-candidate/sound-info-codec.* and sound-info-vendor-test.cpp provide scalar/offset metadata validation against a retained input allocation. sound-info-vendor-RESULTS.md records one genuine known-valid PCM WAV per original-DLL process, with x64 decode/reconstruction and later input immutability checks. This is not arbitrary malformed input safety or a wired Backend WAV_info path. Public70 SampleInformation projects only seven fields, so reuse relevant validation without exposing native pointers or imposing a new public wire structure. On native zero leave caller output unchanged, matching native70; on success validate complete reply before copying the seven scalars.

binding-probe30/probe.cpp and RUNTIME-RESULTS-v1.md show actual same-sample binds A/B/A, a known unsupported-format failure, then successful B recovery. Every image AND suffix remained alive through shutdown. Therefore it does not establish failed-bind old-state preservation, incoming-image reclamation, prior-image retirement at rebind, or asynchronous safety. binding-static32 and binding-retirement38 narratives explicitly leave general retirement unproven; this assessment publishes no private disassembly and performs no new binary examination. Do not substitute permanent history retention, arbitrary history cap, one-bind restriction, or allocating a different native sample for missing native-equivalent retirement evidence.

## Smallest private extent seam, keeping native70 removable

For file_type/set_named_sample_file the public length is already sufficient to bound a client copy (after checking size/budget/pointer under normal caller validity). The two no-length calls need trusted allocation provenance BEFORE reading even a media header. RIFF length, terminator scanning, VirtualQuery readable pages or a guessed maximum are not allocation extent or ownership.

At Audio adoption, expose one narrow private image-view provider from the actual Audio owner to the adapter root. It can resolve an exact cache image pointer to its existing cache entry/length and hold the relevant existing path reference while bytes are copied. Do not register another independently authoritative generic pointer table. Resolution and pin acquisition must be atomic relative to cache decrement/deletion under the adopted serialization policy; do not call increaseReferenceCount(path) in a way that reloads or retargets a different allocation. Preserve exact base identity, reject an unknown interior pointer rather than guessing.

For getSampleInformation's temporary WAV image, use a narrowly scoped owner/view carrying its already-known pointer+fileSize for that call; root lookup may consult this explicit current view before the cache. This is a deliberate private Audio adoption seam, not a new public ClientMiles parameter. Resolve only live exact supplied view and remove it before deletion. No need to alter unrelated producers or parse beyond the known length. Native70 direct mode can leave this view unused, preserving the common public call signatures and removable pipe implementation. A general public pointer from outside these supplied owners remains unsupported until its owner participates; report that limitation before native effect instead of returning invented zero metadata.

A scoped lookup establishes only source extent through serialization. Copy/upload to a sealed, helper-owned buffer before invoking real SDK. The existing resource registry can associate Buffer identity with its owner; samples can retain a binding owner next to their existing identity state, avoiding a second sample registry. Snapshot copying must be an explicit immutable-image policy: if callers mutate a bound image while the SDK legitimately observes it, a one-time pipe copy cannot preserve that behavior. The inspected cache code loads/deletes bytes, but this is not an audit of every buffered external producer.

## Lifecycle transaction and next decision

Before setter effect, allocate/validate sealed helper bytes and suffix ownership, resolve exact OwnedSample and reserve all binding bookkeeping. Record exact S32 result. Zero is native failure, not evidence either old or candidate bytes are dead. Nonzero is successful bind, not evidence the SDK copied all bytes. End retains live sample/binding. Release/shutdown must use the actual reviewed termination/consumer contract before reclaiming held images; callback ACK/coordinator pins alone do not prove vendor readers are gone. Unknown outcome retains transaction state terminally; do not reset to an assumed previous binding. Rebinding must preserve real handle identity, status and future operations, including buffered sample reuse.

The separable next source feature is explicit-length read-only file_type plus the trusted no-length WAV_info extent/projection path, using existing upload/codec pieces. Neither requires pretending sample retention is solved. The two sample setters need a concrete accepted image/suffix retirement contract across success, failure, replacement, end, release and shutdown before being advertised native-equivalent. Exact Audio caller ownership helps locate the seam but does not supply that missing vendor guarantee. No implementation or test execution is authorized by this assessment.
