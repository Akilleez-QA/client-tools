## What initialization and release actually retire

Initialization calls `AIL_set_sample_processor(sample,11,0)` at `0x2cada`; release makes the same call at `0x2ca89`. The wrapper at `0x14d80` reaches processor core `0x2b7b0`.

The core iterates stages 0 through 9 when selector11 is supplied (`0x2b822–0x2b82d`). For each stage it tests the active word first (`0x2b7da–0x2b7ec`). For active ASI stage0 it calls its stored close function with its stored stream at `0x2b814–0x2b81b`, then clears active at `0x2b820`. For active filter stages1–8 it invokes the provider's per-sample close at `0x2b803`, clears the sample-state slot, and decrements the filter count. These field interpretations agree with possessed `Mss.h` definitions of SPINFO/ASISTAGE, SP_ASI_DECODER=0 and SAMPLE_ALL_STAGES=11. The ASI close result is not checked here; the call returning is not by itself a documented provider-quiescence guarantee.

After this cleanup, initialization replaces the descriptor array at `0x2caef`; the prior array is freed at `0x2e657`. Release frees/clears it at `0x2ca96–0x2ca9b`. Work-array cleanup `0x28fb0` frees specific sample-owned arrays; it is not a second unconditional ASI close and does not free the caller's input image. Inactive stage fields may still contain old pointer-sized values; active-bit clearing is not identical to zeroing every field, nor does a stale numeric field alone establish a live reference.

Thus, for calls that reach initialization, old direct descriptors do not survive as current descriptors. Active old provider close has returned before new descriptor installation. This is stronger than merely observing a changed current pointer, but it does not close the provider/consumer escape set. Early bind exits before initialization must not be included in this statement.

## Incoming-image failures are not one category

1. The exact unsupported-WAV/no-provider branch from review32 removes old descriptors but bypasses new address installation. Its image-derived parse fields remain local. This does not generalize to provider failures.
2. The named provider path installs the incoming image at `0x2b750` before calling processor setup at `0x2b759`. If provider open returns null, setup takes `0x2bd81` to `0x2b8af`, clears the stage provider field and returns without undoing the incoming descriptor. Named binding checks the resulting active processor at `0x2b766–0x2b76d` and returns zero at `0x2b779`. The newly installed image remains the direct descriptor source despite zero.
3. **Opened-provider / later allocation failure:** setup calls ASI open at `0x2bd72`, passing sample as user context, fetch callback `0x2eb00`, and descriptor length. It stores the returned stream at sample+0x270 (`0x2bd74`). After provider property calls, setup calls format helper `0x29870` at `0x2bece`. If format changes, that helper calls work-array rebuild `0x29070` at `0x298bc`. Concrete allocation-null checks (for example `0x29098`, `0x290b9`) reach error/zero return `0x29248–0x29255`; helper propagates zero at `0x298c3`. Processor setup then returns -1 at `0x2bed7`, before its active-word publication at `0x2bf3a`. Named bind converts -1 to zero at `0x2b75e–0x2b779`; the generic WAV provider path does so at `0x2b563–0x2b569`.

On that conditional failure path, the new direct input descriptor and opened stream field have already been installed, but normal init/release cleanup skips the inactive ASI stage. No explicit provider close occurs between that failure branch and return. This is a concrete missing cleanup edge in the inspected control flow, not a reproduced provider leak or use-after-free. Actual failure reachability under the intended codec/configuration, provider-owned retained references, and any independent cleanup remain unproved. It specifically defeats assuming “a later ordinary init always close-calls every previously opened attempted codec.”

The generic WAV provider path only tests processor return against -1; the named suffix-provider path additionally checks active processor presence. Preserve their actual native return behavior rather than imposing one shared interpretation of every zero/nonzero result. On normal successful ASI setup the active word is finally set; optional DATA_START_OFFSET/DATA_LEN queries may adjust the new descriptor at `0x2bf16/0x2bf34`. Those adjust the incoming-source descriptor; they do not establish a source copy or validate every provider-supplied offset.

## Consumer and synchronization evidence, and where it stops

The ASI fetch callback `0x2eb00` retrieves the sample's current descriptor array and copies from descriptor source+cursor at `0x2eb6b–0x2eb77` (and the next-buffer path at `0x2ec16–0x2ec24`). It has no local mutex acquisition in the examined routine. ASI processing at `0x2f5f7` loads the stream from sample+0x270 and process function from sample+0x208. A traced caller chain is `0x32070` sample-status traversal → `0x30510` → `0x2f330` → provider process. The traversal only selects status4 samples; init/release mark the sample's driver status entry1 before cleanup. That blocks later traversal selection but says nothing alone about a consumer already executing.

Global mutex helper `0x1090` is conditional on RVA0x69b08. The preference-table base is0x69a58, so this is index44, matching header AIL_MUTEX_PROTECTION; preference initialization writes1 there at `0x11e7`. This narrows review32's unknown enabling-global identity. It does not establish the actual configured value at all times. Export wrappers participate, and timer worker `0x1590` conditionally acquires the same mutex before timer callbacks (`0x15d0–0x1604`). A driver service path also acquires it at `0x34127`. Processor setup conditionally releases one mutex ownership level before provider open (`0x2bd5a`) and reacquires at `0x2bd77`; recursive outer-wrapper depth must be accounted for before calling that interval globally unlocked.

The still-unclosed graph is precise: all ingress/lock ownership for the mixer chain; external ASI open/process/close implementations and their fetch/lifetime behavior; filter/sample-driver callbacks (including release's indirect call at0x2ca82); and references held across callbacks, provider work or asynchronous driver activity. External function pointers were identified, not resolved to verified provider implementations. No whole-binary or external-module no-escape proof is claimed.

**Decision:** direct PCM/no-provider state replacement and synchronous active-stage close ordering are now better specified. Generic completed-rebind retirement and release-wide quiescence remain unsupported, with the inactive-opened-stage branch an additional concrete obstacle. Do not free prior inputs solely from current-pointer replacement, native zero/nonzero, or a zero coordinator pin count. Do not substitute permanent retention, a history cap, a one-bind limit, or a different native sample for the missing contract.
