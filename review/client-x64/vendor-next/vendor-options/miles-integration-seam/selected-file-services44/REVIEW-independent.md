# Independent selected-services source and portable review

Read actual selected_services header/cpp, production delta, FileInvocationJob/context propagation, portable tests, macro wrapper, runner and raw build/run results before reading any implementer narrative conclusions. No rerun, compiler or SDK/runtime execution. Current frozen input hashes match freeze-v1.json. Raw command compiles selected_services.cpp, file_channel.cpp, codec.cpp and tests only; it does not compile/run SessionFileOwner or actual FileInvocationJob/EngineFileWorker.

No concrete defect found in the bounded table-selection/value adapter. Each FileServices owns a distinct immutable Table with four selected function pointers and retained lifetime pin. Invocation copies that service owner. FileSessionContext stores the selection const and the source delta threads it into FileInvocationJob instead of canonicalServices. These latter owner/job edits have source review only in this gate.

Open preserves uint32 status verbatim and uintptr handle separately: fixture A returns status7 with local handle0, fixture B returns0x80000001 with handle0x100000023. Tests verify full local handle before framing and wire publication independently; close/seek/read callbacks also assert the original untruncated local handle. Failed open returns no wire resource and a supplied publication identity is rejected, with no implicit close. Signed offsets/results include INT32_MIN and-1 across all three seek origins. Read tests distinguish zero/full/short results, copy exact bytes with untouched sentinel after extent, and reject a returned count beyond the requested buffer. Close invokes once, duplicate Invocation entry does not invoke twice.

Interleaving is meaningful but sequential: A's Invocation is built, B's table is selected, then A executes before B; later seek/close order reverses. This detects a latest-global-table implementation. It does not test concurrent invocations, which remain unsupported by Invocation's executor contract. Lifetime tests release caller table/pin/context references before invocation, assert they stay alive during and after normal/throwing invocation, then expire when Invocation is destroyed. All four callback throw paths are captured as CallThrew; completion encoding rejects them and preserves the tested output length/first-byte sentinel. The supplied nonnull lifetime object is still a caller contract, not proof that it actually owns the callback code/state.

Macro boundary is narrowly test-only: native35_compat.h includes stdint before defining _WIN32/_MSC_VER/__stdcall, includes only the plain callback declaration header, then undefines all three before other source/system headers. It is force-included only by this Linux portable command. This permits value tests but provides no stdcall, actual MSVC, Windows or possessed SDK type-equivalence evidence. Production declaration/header was not made portable by weakening its guard.

Raw result reports build_exit0/run_exit0 under strict Clang C++11 ASan/UBSan and run.log reports316 checks. This is316 assertions across the scenarios, not316 independent behaviors. The empty build log contains no warnings/errors. The runner itself hashes inputs before execution; the separately retained after-input record and this review's current hash comparison support unchanged inputs, not an independently observed runtime.

Gaps: no real owner/job execution or owner constructor rejection test with missing services; no multiple SessionFileOwners selecting different tables through actual queued jobs; no async worker/TLS/shutdown or callback registration; no null-table/default-file or replacement semantics; no native-width x86 ABI check. Failed-open fixture uses local handle0, so status0 with a callback-written nonzero junk handle is not separately tested. Null-selection tests cover each missing callback and missing pin at retain(), plus a default invalid Invocation table, not every invalid field at every composition layer. These gaps are accurately bounded by the actual compiled source list. No blanket approval for the larger callback/file pipeline follows.
