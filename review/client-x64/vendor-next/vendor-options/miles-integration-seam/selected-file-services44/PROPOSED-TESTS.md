# Proposed discriminating portable tests — not executed

Use real candidate codec/decodeRequest and Invocation/encodeCompletionInto/decodeReply. Do not replace selected-services with a fake selector. A portable compiler may include the unchanged native35 header through explicitly test-only `_WIN32`, `_MSC_VER`, and empty `__stdcall` definitions in a compatibility include; label that run value/ownership-only, never calling-convention evidence. Prefer a separate test target with no engine objects. Any future compile invocation must document those substitutions.

1. **Two selected tables, interleaved operations.** A and B have distinct open/close/seek/read functions and counters. Construct A Invocation, then B, then invoke A after B is retained. A returns status 7, handle 0; B returns status 0x80000001 and a uintptr sentinel. Confirm exact statuses, correct table counters and opaque published wire identities independent of local handles. On a 64-bit portable target use a sentinel above UINT32_MAX. Interleave read, seek and close; confirm each table alone receives its own handle, bytes and arguments. This fails any hardwired canonical service or global latest-table adapter.
2. **Zero handle success and non-1 status.** Decode a real FileOpen request; invoke A; publish a nonzero File wire identity. Decode its reply and expect returnBits 7 and that identity. For a separate failed open status 0, permit no published identity and do not call close. A zero local handle must never change the success status.
3. **Signed seek fidelity.** Use offsets -17 and INT32_MIN and valid origins 0/1/2. Assert the selected callback receives exact signed offset and returns INT32_MIN or -1 unchanged. Expect the matching uint32 representation in the reply, without saturation or conversion to generic failure.
4. **Read and close fidelity.** Assert exact handle, original requested count, accessible buffer and output bytes, including zero-length read and short/zero read. Close runs exactly once with handle 0. Repeat invocation returns false and cannot call close again. Oversized returned count remains ReadCountOutsideBuffer and cannot be encoded as normal EOF.
5. **Exception and retention.** Construct Invocation, release the caller's FileServices and external callbackLifetime owner, and verify its weak lifetime observer stays live before, during and after the callback until Invocation destruction. Throw from open/read/close/seek; confirm CallThrew, no normal encoded reply, no automatic retry or implicit close, and lifetime retention through the uncertain result. On open throw, do not invent a handle or claim side effects are reversible.
6. **Actual FileInvocationJob plumbing.** To test the modified job source portably, compile the actual FileInvocationJob.cpp against a narrowly documented fake Windows event API and controllable EngineFileWorker submission implementation. Do not compile owner37's portable_job.cpp, which replaces the path under test. Queue A and B jobs, drop external service owners, execute queued callbacks in controlled order, and assert selected results plus lifetime retention. Exercise submit false (including queue allocation failure), job-construction allocation failure before submit, callback completing before submit returns, and job retained after caller releases its shared_ptr. This cannot validate real Windows synchronization or TLS.
7. **Owner linkage.** Adapt an owner37 portable fixture to accept provided services rather than select its own. Pass different const services through two FileSessionContext objects and check owner receive/poll/reply/ACK preserves selection. Ensure owner retains table/context for successful unclosed files and failed/unacknowledged operations. Never interpret job completion or ACK alone as permission to destroy the session/engine.
8. **Pre-invocation rejection.** Each missing callback and absent callbackLifetime makes retain throw before any callback executes. Invalid context-aware services make SessionFileOwner construction refuse before session registration. No replacement/null-default behavior is asserted.

No test above establishes operational callback registration, native64 availability, engine TLS readiness, background I/O, host ACK delivery, vendor worker termination, or ABI fidelity. Reentry needs separate composition tests once the facade guard and terminal failure path exist, including a callback that catches the guard's exception and tries to return success.
