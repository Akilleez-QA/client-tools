# Next source outline: session-owned file callback registration

Not implemented or executed. Current Coordinator::registerCallback requires a valid Driver..File resource. Audio installs the global Miles file callback table before opening the driver; FileOpen has no preexisting file binding. Therefore ordinary resource registration cannot represent this ownership without a false handle.

Extend the **existing Coordinator registration type**, not the wire handle kinds or another lifecycle framework:

- Add an internal scope discriminator `ResourceScoped` / `SessionFiles` to Registration. Keep existing registerCallback and all its handle checks unchanged. Add one trusted `registerSessionFiles(session, registrationId)` method that requires the correct live incarnation and Active state and permits only one session file table. Reuse the same monotonic registration IDs, registration capacity, callback capacity, sequence/frontier and close tracking. A SessionFiles registration has no resource handle; do not pass its unused storage through resource validation or matching.
- The control owner creates that registration before admitting/sending the native-shaped set_file_callbacks operation, so synchronous callbacks cannot precede their registration. The existing ordinary admission accepts an empty resource list; it still pins an active admission/session. No driver/file identity is minted until an actual corresponding resource exists. If setup fails, retain the registration and its outcomes through the existing failure/drain path until vendor production is proven stopped.
- For incoming FileOpen/Close/Seek/Read, the trusted dispatcher selects this session registration after checking the connection incarnation and owned file26 request association. It never lets a wire flag choose registration scope. Keep existing CausalReverseIo cause==activeAdmission and Unsolicited cause==0 checks; timing alone cannot classify vendor-thread callbacks. Reuse admitCallback and CallbackId accounting. In Failed, recording a late callback remains an observation, not permission to execute it.
- For SessionFiles readiness, report the active session admission as a request pin when one exists; callback pins/frontiers remain the existing counts. ResourceScoped readiness retains its current exact-resource accounting. Keep vendorTerminationUnproven=true: zero pins does not establish vendor shutdown. Before beginning close of the session table, require existing beginDrain so ordinary game admission is closed; cleanup admission and late-observation accounting continue unchanged.

Actual memory ownership stays with the backend session owner. Its existing Invocation lifetime pin keeps session/file context alive; non-open calls additionally retain the exact Binding. An open success must be published into the owner file registry before its response, using callbackResult rather than local-handle truthiness. Job completion is not callback acknowledgment or permission to retire a file. The owner retains its own session/worker reference until after checked join, so a last job-pin release on the worker cannot trigger worker destruction on itself.

Minimal owner sequence: start TLS-ready worker → register session file table → install SDK callbacks → open driver. On partial install or normal removal: beginDrain → keep receiver/worker servicing stop/close/shutdown → prove vendor callback termination → resolve admitted completions and queue necessary known-file closes → stop submitters/drain-and-checked-join → release registration/context. A failed join retains ownership/resources. Uncertain open/close outcomes cannot be retried or automatically declared closed.

Required review distinctions before a future implementation: preserve resource-registration validity; share existing capacities/monotonic IDs rather than bypass them; reject duplicate session tables; count an active admission and outstanding callbacks while no driver exists; retain failure/late-callback accounting and the independent vendor-termination requirement. This outline changes no schema, worker scheduling policy or production source and grants no runtime authorization.
