# Actual input owners: bounded source audit 39

The normal sample cache exposes a concrete shared allocation lifetime that could identify a private transfer owner without making rebind return a retirement predicate. **The same is not true of all actual buffered callers.** Raw pointer binding alone supplies neither owner destruction nor mutation notification, and the TCG owner is outside the examined source. This audit does not select an architecture or establish that original owner destruction is vendor quiescence.

Scope: read-only clean product HEAD `49d0eeed4ddaa177d7a93ea396c37c3d9b9942da`; `git status --porcelain` empty. Source paths below are relative to `/home/akilleez/Work/swg-source/client-build-next`. ## Cache and transient images

`src/external/ours/library/fileInterface/src/shared/AbstractFile.cpp:52–66` allocates `new byte[fileLength]`, reads the file and closes it; closing/deleting the AbstractFile does not destroy the returned image. In `src/engine/client/library/clientAudio/src/win32/Audio.cpp:1508–1530`, `cacheSample` first passes this image to the duration helper, then installs it in the existing SampleCacheEntry. A hook only after installation would therefore miss its first bind.

The cache is keyed by path through CrcString comparison, not by HSAMPLE. `cacheSound` (1539 onward) creates or reuses the entry and increments references; it can create a metadata-only entry and populate its bytes later. `SoundTemplate.cpp:68–83,122–138` owns references for template sample lists. `Sample2d.cpp:25–75` and corresponding Sample3d/Stream wrappers acquire references on copy/setPath and drop them on destruction. Several handles can therefore use the same cached allocation. Bind at Audio.cpp:2836 uses that shared address; 3D uses the same cache through `AIL_set_sample_file` at2925. An owner solution limited to named binding would not yet cover this latter public API.

`AudioNamespace::decreaseReferenceCount` (347–373) deletes the byte array and erases the entry at zero references. Shutdown's remaining-cache cleanup (1450–1465) deletes images after `AIL_shutdown` at1438. Normal `releaseSampleId` (3379–3409) stops/ends, releases the native sample, then erases the wrapper whose destructor drops its cache reference. No client writes to cached image contents after loading were found in the examined clientAudio uses; the pointer remains mutable at the SDK boundary, so this is not a vendor immutability proof.

Failure is not uniformly a neatly scoped owner lifetime. The duration helper (4427–4464) releases its fresh HSAMPLE only inside the nonzero-bind branch; zero or null image leaves the allocated handle unreleased in this source. `getSampleInformation` (3692–3728) deletes its separate image after the helper returns, including a zero bind. Cache loading retains its image even when duration binding fails. Ordinary playback failure at2897/3106 calls stopSound, but the newly created sampleId is assigned to Sound2 only on success at2885; createSampleId (569–695) has already inserted the wrapper. Thus the failure path is not source proof of release of that newly allocated handle. These are existing lifetime/control-flow gaps, not newly demonstrated vendor reads after free.

## Buffered callers

Audio.cpp:5328–5384 maintains one HSAMPLE for sound and one for music. Subsequent plays stop/end the previous sample, rebind the same handle, ignore the signed bind result and start it. Stop only calls stop/end; it does not release the handle, detach the image, or tell an owner that bytes are no longer referenced. No separate buffered-handle release/reset appears in this file; Audio shutdown supplies the enclosing SDK shutdown.

The two caller families found by a full `src` search are:

- Debug parser `src/game/client/library/swgClientUserInterface/src/shared/parser/SwgCuiCommandParserAudio.cpp:280–319`: two static 4 MiB allocations are reused. It stops the relevant sample **before `fread` overwrites the same allocation**, then binds the new length. A full-size read returns “File too large” after the overwrite and without a new bind. Its destructor (76–89) deletes the buffers without a local stop/release. Equal address is therefore not equal content or bind generation. A copy refreshed only on a later bind misses mutation that precedes binding or is followed by no bind. This is an actual client mutation pattern, not proof that Miles subsequently reads the modified old binding.
- TCG bridge `.../core/SwgCuiTcgManager.cpp:154–196`: callbacks forward raw `char*`, length and WAV/MP3/OGG format; stopAllSounds forwards only stop/end. No retain/release token or buffer mutation/free callback exists here. `src/external/3rd/library/libEverQuestTCG/src/win32/libEverQuestTCG.h:38–42` likewise specifies only raw callback types. Its cpp stores callbacks and passes the table to the dynamically loaded SWGTCG implementation (532). Release calls Manager::shutdown, which calls the external Shutdown export (600–604). The examined bridge cannot establish allocation identity, sharing between sound/music, reuse, or the ordering of final audio stop versus buffer destruction inside that DLL.

## Exact cost and remaining limits

Preserving the public native-shaped `set_named_sample_file` signature is compatible with *additional private owner metadata*, but cannot make that metadata implicit in arbitrary pointer+length calls. Cache coverage would require registration before the first duration bind, association of the byte extent with an allocation generation shared across handles, deletion notification at both normal and shutdown frees, and a path for transient getSampleInformation images. Path alone is insufficient across unload/reload; address alone is insufficient after allocation reuse. Native zero must not unregister a still-live client owner.

Buffered coverage additionally needs mutation/generation notification at the actual writer, and an owner destruction/retention contract from TCG that this source does not supply. A stop callback is not a demonstrated detach boundary. This is extra private API and caller integration cost, even if the public Miles signature remains unchanged; it is not achievable by replacing only the binder body. A copied snapshot also does not automatically preserve original aliasing across simultaneous bindings or original subsequent writes.

Mirroring an existing asset lifetime can avoid *inventing an earlier per-rebind reclamation point*, and the immutable-looking cache is concrete positive evidence for that narrower idea. It cannot turn the original client's failure leaks/free ordering into a correctness guarantee, close retirement38's provider consumer graph, or make unknown TCG ownership known. No general owner-correlated replacement for per-bind ownership is established by this bounded audit; the cache subset is materially better specified than buffered/opaque inputs.
