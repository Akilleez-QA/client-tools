# Coordinator state model: approved bounded admitted-work slice

Scope: a bounded deterministic admission/ownership state machine only. No vendor calls, OS thread dispatcher, client shim, transport pipe, pointer freeing or production edits. Inputs are already decoded typed values; one control-dispatch thread owns the model. Its rules are to be tested independently against externally authored scenarios before assembly.

## Proposed API

- Constructor: immutable nonzero `SessionId` (uint64), explicit bounded request/callback/registration/resource limits. All externally supplied identities carry this incarnation; stale sessions reject without state change.
- `admitRequest(session, admissionOrdinal, lane, lease, action, resources)`: action Ordinary/AcquireLock/ReleaseLock. IDs are exact next accepted sequence, nonzero; rejected attempts do not consume sequence. Only one vendor request is executing; no arbitrary nested game/vendor dispatch is admitted. Resources use existing MilesWire::Handle, checked for nonnull canonical structure and deduplicated for pins; resource liveness remains the central resource registry's responsibility until integrated.
- `completeAdmission(session, admissionOrdinal, outcome)`: ordinary request must have no outstanding causal callback. Acquisition/release modifies lease depth only after a completed vendor call. Lock ownership is lane+session+lease, not host OS recursive-mutex ownership. First acquisition creates a fresh never-reused lease; recursion requires current lease; foreign lane cannot execute while held. Vendor/transport failure is distinct; transport failure moves to Failed instead of fabricating successful unlock.
- `registerCallback(session, registrationId, resource)`: exact typed resource association and bounded registration identity. No actual SDK registration is implied.
- `admitCallback(session, registrationId, kind, causalAdmissionOrdinal)`: typed kind CausalReverseIo or Unsolicited; separate callback identity namespace from forward requests. Causal requires the exact executing request; unrelated worker callbacks cannot borrow the active request's identity. Unsolicited requires causalAdmissionOrdinal0. Issued callback sequence belongs to its registration and is monotonic.
- `acknowledgeCallback(session, callbackId)`: out-of-order acknowledgments retained in bounded state; contiguous acknowledged frontier advances only past every earlier admitted callback. Callback completion is protocol delivery/handling acknowledgment, not vendor callback termination.
- `beginCloseRegistration(session, registrationId)`: closes new forward registration use and records current callback frontier. Late callbacks may still arrive while closing; they extend the close frontier rather than being lost. Repeated close is idempotent. No pointer is freed or registration retired.
- `closeReadiness(session, registrationId)`: reports request pin count on the associated resource, issued close frontier, contiguous acknowledgment frontier, and `vendorTerminationUnproven`. That last condition always remains unresolved by this model. Relevant raw vendor observations can be recorded separately but never converted into an opaque true-quiescence grant. A returned SDK unregistration/release is not automatically proof no callback can occur.
- `beginDrain(session)`: Active→Draining. Refuse new ordinary forward requests, but service already-admitted causal reverse I/O, callback messages/acks and request completions. Whether an owned lock needs a specific cleanup action must be explicit; do not block the very unlock required to drain.
- `fail(session, reason)`: Active/Draining→Failed, permanent for this incarnation. Notify terminal failure for pending client requests and forbid further vendor admissions; retain unresolved request pins/callback state as evidence. Failure does not cancel an executing vendor call or demonstrate memory can be reclaimed. No implicit restart or successful lease release. A fresh process/session requires a new model.

## Invariants and deliberate limits

At most one executing forward vendor operation. A lease cannot transfer between client lanes. Every active request keeps its resource pins until actual completion observation; client-facing terminal failure alone does not release them. A causal callback keeps its parent request incomplete until acknowledged. Registration close completion cannot be inferred from the current frontier: later callbacks extend it, and vendor termination remains independent. Callback counts, pins and IDs never wrap or silently evict entries. Capacity failures are explicit and state-preserving; this does not establish equivalence to the original media capacity.

No claim of liveness under an unresponsive peer, actual callback affinity, original Miles exclusion, FPU equivalence, valid vendor lifecycle, or actual asynchronous cancellation. No policy that frame-batches callbacks or silently queues a synchronous reverse call behind its own blocked parent.

## Prospective validation

Peer authors independent scenarios before seeing code: cross-session/replay rejection; foreign lock owner; recursive acquire/release; failed admission sequence; resource pins across requests; causal callback parent mismatch; unsolicited callback during an active request; out-of-order acknowledgments; close plus late callback; drain while request/callback/lease outstanding; failure with unresolved pins; ID/capacity exhaustion. Native v120 both ABIs Debug/Release and host sanitizer runs, with separate discriminating mutants for lease owner bypass, early frontier advance and pin release on failure. No vendor DLL is linked or called.

Parent approved implementation with explicit cleanup authority in Draining. APIs use admissionOrdinal minted after scheduler selection; this is not a wire correlation ID. Deferred intake, wire replay tracking and fair queue selection remain outside the model. Failed retains pins and last lease diagnostics until actual completion observations; nested vendor API reentry is outside the scope, not asserted impossible.

Final scope: registration identities never retire or reuse, so the default64-registration bound is a total session-lifetime experimental cap, not a validated production capacity. completeAdmission records actual return; it does not represent a successful general Miles result. Lock/unlock are void calls whose observed return permits the modeled lease transition. Vendor results belong elsewhere. Readiness explicitly exposes both requestPins and callbackPins in addition to acknowledgment/frontier and the unresolved vendor termination condition.
