# Bounded upload before the live slice

Prospective2026-09-30. The published architecture requires BufferBegin/Chunk/Seal to produce complete immutable host input before a genuine Miles image bind. Existing codec bounds and RetainedBuffers do not assemble chunks. Implement that missing per-upload state, with no vendor calls or ownership graph of its own.

Constructor takes declared uint32 byte length and caller-authorized per-upload limit. The session owner must reserve its aggregate budget first and bind this object to a live Buffer resource; neither registry/session policy nor resource retirement is claimed here. Sequential chunks must exactly start at the received prefix and stay within declared size. This deliberately rejects gaps/overlaps/replays rather than collecting arbitrary intervals. A seal succeeds only for complete coverage. Empty upload may seal structurally; this does not authorize passing empty or arbitrary data to vendor parsers.

Only copySealed publishes data, as a distinct owned vector, so destroying/releasing an upload cannot invalidate sample-retained bytes. No escaping pointer/view. Immutable sealed input rejects further append. Allocation failures before publication leave state/output unchanged using construction or copy/swap. Payload limit is not an exact process-memory/RSS limit; sealed copying temporarily duplicates input and must be budgeted by session owner.

Tests: tiny uneven validchunks, exactempty, gaps/overlaps/replays/nullsource/overflowlength, prematures eal, postsealwrite, source mutation afterappend, destination ownership aftercopy, limit rejection, and >1MiB complete input assembled from boundedchunks to ensure frame limit does not become assetlimit. Nativev120 fourconfigurations and parent sanitizers. Negative control accepting premature seal must fail. This closes only chunk assembly mechanics; real64→32pipe, coordinator handlers, genuine bind and wholeengine acceptance remain dependent work. No product edits or publicvendor assets.
