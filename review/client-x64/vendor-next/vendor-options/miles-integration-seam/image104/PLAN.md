## Concrete next slice

Implement WAV_info as the next readonly upload consumer in99, with one private scoped source view supplied at the real Audio call site. The view establishes the otherwise missing extent through upload. Do not couple this query to sample binding retirement. The next executable check is a portable test of the actual extended99 Core/Session, real upload/codec/reply path and the scoped view, using an explicitly labeled Channel/Runtime supplier as98 does. Tests do not run the host handler or SDK; a separate native object gate covers the actual host call declaration. Neither gate is executed here.

The minimal view is **one Session member**, not a cache scan, new registry, global pointer map, TLS active owner, public API argument, or generic resolver callback. Proposed private class `ScopedSourceImage` is noncopyable; construction associates `(exact base pointer, positive uint32 extent)` with the existing selected Session, requires the existing forward guard and serialized command owner, and rejects an already active view. Destruction removes only its matching token/view and performs no RPC. `Session::sourceExtent(pointer)` accepts only that exact live base and rejects unknown/interior/stale pointers before reading any bytes. Scope lifetime encloses the unchanged public call. Source allocation ownership stays with the actual Audio caller; this class is a bounded borrow, not a new allocation owner or a claim to pin arbitrary memory.

A declaration/implementation alone would not make arbitrary WAV_info pointers supported. The private root/adoption layer must arrange the scope where the extent and live owner actually exist. This plan deliberately does not author an unconnected view and advertise ownership as solved. Actual adoption and its serialization checks are still separate product work.

5. Update the paired private contract explicitly, then freeze source/tests before executing. Original private-v3 opcode1 has no implemented99 endpoint; old peers return Unsupported, never a fake projected success. Public70 is unchanged.

Recommended exact new opcode1 contract: request resource=sealed Buffer, null target, value0=known N equal to its declaration, output_mask=1, all other fields/spans zero. Success result has S32 return_bits; if nonzero, value[0..6] carry format,bits,channels,dataLength,rate,samples,blockSize, respectively, with the first three encoded as raw signed bits. value7, all handles, callbacks, null masks and byte/text spans remain zero. Native0 and transport refusal require all metadata values zero; refusal also requires return_bits0. This is a deliberate amendment of the older generic API-MAP byte-SoundInfo proposal and needs paired source review before implementation; it must not be silently called the old44-byte contract.

Reason for this smaller projection: public70's SampleInformation contains precisely those seven scalars (`ClientMiles.h:169–175`), and actual native70/native_calls60.cpp:264–279 copies them only on nonzero status. Existing sound-info-codec.cpp:39–55 validates data/initial pointer offsets too, but public70 exposes neither pointer. Requiring those unused offsets to reside in the input would impose extra rejection beyond the chosen native projection. Reuse the actual envelope codec's scalar field serialization and signed-bit conversion; do not ship/reconstruct pointers merely to reuse an older44-byte helper. The old genuine-WAV evidence still covers its own prototype, not this new projection or arbitrary malformed vendor input safety.

## Setters: precise retained-owner seam, still not enabled

Both setters can reuse93 upload and the existing sample registry identity. Before entering SDK, associate an owned `(image,suffix)` pair and pending candidate with the existing OwnedSample row, preserving original sample identity. Explicit-length named setter supplies its extent directly; the no-length setter uses the exact scoped cache view above. Transfer/retain the sealed upload's owner as appropriate and account old/pending images and suffixes before effect. BufferRelease may retire the transfer identity but cannot free bytes still owned by a sample.93 currently releases all query storage and blocks unrelated operations during staging; it must not be reused unchanged as a setter and then free inputs on return.

`sample-pipe29/prepared_input.h` is preparation only, builds on a different retained-buffer store and extra copies, and explicitly says no vendor retirement policy. Do not adopt its second store blindly into99. Existing sample/resource rows are the ownership attachment; no second sample registry.

The binding31 decision remains specific: successful same-sample A/B/A and failed F followed by B were observed with every image and suffix retained through shutdown. Neither status proves old or attempted image retirement. Product's end/stop leaves samples reusable, and debug buffered code overwrites its original client buffer after stop/end; remote copying must preserve the selected consumer behavior rather than promise universal immutable external ownership. Zero may leave old and/or candidate references, so returning zero must not roll back to guessed ownership. Success must not retire the predecessor without the accepted vendor boundary. Release/shutdown return and callback ACK are not interchangeable lifetime proofs. Unknown outcome stays terminal and retained. No permanent history, arbitrary bind count, replacement native sample, one-bind restriction or end-time free is selected here.

Consequently no complete setter source is authored104. The concrete dependency is an accepted detachment rule for success/zero/release on supported formats, not allocation code. The next bounded source implementation should be the scoped readonly WAV path above; it can be tested without claiming any setter lifetime rule.
