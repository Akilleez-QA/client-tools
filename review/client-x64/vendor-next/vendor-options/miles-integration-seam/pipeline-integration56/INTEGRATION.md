Passing those unchanged originals can attempt a second install. The29 extraction provides separate admitted common bodies but expressly says they are not an SDK callback table. The adoption change needs an explicit, reviewed typed callback adaptation/engine registration choice that preserves real supplied semantics while bypassing only the legacy TLS prologue on this admitted worker. Do not silently ignore a user table in favor of canonicalServices, probe isThreadInstalled, pre-clear global once, or add an extra threadInstall. 3. **No actual native-shaped pipe installer reaches the new host installer.** Existing47 Session/Channel only issue ordinary generic replies, while host38 Backend's common check (`startup-bridge23/backend.h166`) rejects nonzero callback identity. On host dispatch opcode28 before blanket callback rejection, using actual Backend started/shutdown state and independent admitted Scope41 origin. Preserve generic validation for every other opcode.

4. **Old destructor/error flow is incompatible with a live callback owner.** Guarded47 Session::~Session121 only clears selection; LiveChannel members then destroy ChildProcess, whose `common.h54–66` terminates/waits child. Host Backend::~Backend34–36 can call AIL_shutdown during stack unwind. Neither is a proven close/ACK/engine-worker rendezvous. Adopt a root-retained failed session plus explicit terminal host boundary before enabling SDK callbacks. Host death cannot clear client FileRecords. Current53 failure loop retaining all objects (162) and host50 fatal destructor are candid incomplete policies, not a normal Session::close implementation.

## Synchronization and ordering assessment

- Client53 ready signals only after Endpoint and Coordinator creation. Preparation success follows real worker Started and mapper/owner creation. Shared observation Tickets outlive a failed wait; slot reset happens before its done signal. Post's caller serialization prevents a second command from replacing a pending Returned ticket. Callback loop never waits on FileInvocationJob, so a command's PendingCallback join does not stop ACK intake. Pre-registration admission numbering survives preparation.
- Host50 producer mutex and work/reply/consumed/done events keep each stack ticket alive through the I/O owner's final access. Recursion check precedes mutex entry. Consumer validates/copies/publishes first; owner sends exact ACK and waits for full write before releasing the SDK callback. No false-ACK or concrete ticket UAF was found in the bounded code. Windows event visibility/compiler execution still needs native acceptance; portable fixtures do not test it.
- Endpoint::pump performs at most four synchronous progress iterations. Host50 correctly continues when no I/O event is pending; client53 revisits after its2ms tick. Existing common.h pauseForIo yields when no pending event, so no concrete no-event deadlock was found there, but its10-second receive watchdog must not govern idle host command waiting. Partial write completion is sendBusy becoming false, not send accepting a copied buffer. Client markReplyQueued means accepted send, not host consumption; only the later exact ACK retires the operation.
- Host can finish its ACK write and issue another reverse request before client receives that ACK; FIFO callback-stream order delivers ACK first. Client50 routes the older-ID ACK before new monotonic intake, then publishes/open-consumes state before the following read/close. Forward reply can arrive first on the separate command pipe; runtime.returned waits while cb owner completes this ordering.
- On53 failure, the callback endpoint is cancelled/drained on its owner and no new engine work is admitted. Pending real file jobs and all open records remain retained. A blocked host callback sees peer failure or its active deadline and terminates; it does not return EOF. Already-running engine work is not cancelled or joined by that fact. Callback arrival after installed state is terminal cannot resurrect the client coordinator.

## Deliberately unresolved before operational use

Normal shutdown requires actual producer termination, host ticket/token obligations, client all-file-state/ACK/pin settlement and worker drain/join. Neither runtime exposes all proofs today. Zero reverse rows, child exit or AIL_shutdown return alone is not an all-files-closed proof. Lock/unlock remains unsupported by53's Ordinary/zero-lease interface and cannot be reinterpreted as ordinary calls. The paired patch must also carry the plain public failure containment instead of allowing existing private Failure/ReentryDenied exceptions to unwind into engine STLport TUs. These are separate implementable follow-ups; this plan does not approve an end-to-end runtime gate.
