# Senior replaceability review 24

Status: temporary bridge; replacement boundary proposed, not full-client fidelity or backend substitutability established. Independent source review; no peer review reports read, no vendor/engine/allocator runtime probes performed. The user wants the bridge discarded when a native x64 Miles implementation or validated alternative becomes available. That requires removing protocol obligations from the caller, not merely making the transport interchangeable.

## Decision

Introduce a small typed **startup-only client boundary now**, implemented by the existing bridge adapter. Do not call it a complete audio backend. Preserve the frozen startup23 composition as evidence; stage modifications separately. Establish the full replacement contract below before migrating playback. A compile-time construction function selecting one implementation is sufficient. A plugin loader, general provider registry, or universal command bus is unnecessary.

The durable boundary belongs immediately below existing Audio/Sound policy and above SDK calls. Sound priority, category/master gain calculations, fades, sample cache policy, looping decisions, SoundId/SampleId mapping and user-selected fallback remain in clientAudio. The backend performs requested rendering/resource operations and reports their outcomes. A native implementation must compile without MilesWire, frame codecs, host process launch, coordinator, named pipes or protocol registries.

`startup-bridge23/backend.h::Backend::execute(Header, Call, vector)` is a host-side SDK dispatcher, not this boundary. It owns registry/resolver, `HDIGDRIVER`, `HMODULE`, retained metadata inputs and wire handle; `startup-bridge23/bridge.cpp::Client::call` consumes opcode/Call and returns OwnedReply. Putting either behind a vtable leaves all wire semantics in the caller. `protocol-candidate/miles_wire.h` is an SDK-oriented IPC schema: resource kind/slot/generation, lock leases, causal IDs, buffer uploads and transport status. These are legitimate bridge internals, not universal audio obligations.

The smallest complete eventual interface consists of typed device lifecycle/configuration; sample and stream lifecycle/playback/position/loop/gain/rate/reverb/spatial operations used by these sites; listener and room settings; metadata/diagnostics; completion registration plus execution/lifetime rules; and the file service supplied by clientAudio. The existing API-PARTITION.md is a useful checklist, not a 62-slot interface specification or proof of executable coverage. Keep the currently observed preferences typed (mixer channel count and premix buffering intent); do not expose arbitrary pointer-sized SDK preference values as portable backend commands.

## Narrow startup seam that is justified today

Expose ordinary local methods with named parameters/results for startup, driver creation, queried mixer channel limit and speaker layout, owned version/error text, and shutdown. Use one opaque local device identity if the narrow slice needs it. The adapter maps it to its private wire driver handle. A diagnostic result should distinguish absent text from empty text where the underlying call can do so. Transport failures cannot masquerade as empty strings, a failed vendor open or successful zero-valued preferences.

Do not collapse the historical order into an opaque `initializeEverything()` that chooses stereo fallback inside the adapter: Audio presently selects a provider, logs the initial failure, falls back, updates `s_soundProvider`, and disables audio only after the second failure. Likewise the experimental startup23 backend accepts only 22050/16/stereo/zero flags; making the method generic in its signature does not establish other configurations work.

The production contract should describe the backend operation, but this first seam may retain Miles-specific startup configuration with an honest startup-only name. Do not freeze redistribution-path mutation or Miles version syntax as requirements for every future renderer. Unsupported operations should fail explicitly; a startup-only fake must never be accepted as a full-fidelity playback backend.

## Callbacks, execution and shutdown are part of the interface

`reverse-file-seam20/ClientAudioFileCallbacks.h` is correctly a local service rather than an SDK callback table or wire structure. It states synchronous execution on the calling client thread, required engine/TLS lifetime, serialization with all original callbacks and operation pins. It does not provide the missing executor. The original callbacks' single `once` flag and `PerThreadData::threadInstall(false)` do not authorize arbitrary threads, much less one new worker per request.

The backend must document which calls can invoke local file service synchronously, which completion callbacks may be nested, and how callbacks are admitted during waits and shutdown. The pipe implementation must independently route reverse responses while the vendor lane is blocked. A native implementation must obey the same externally observable callback ordering/exclusion contract without implementing causal IDs or callback acknowledgements. Unknown permitted reentrant SDK operations remain a validation gate; do not make all methods recursively callable by declaration.

Use explicit installed/running/closing/closed state and ownership. Reject new work after closing begins, retain resources while admitted operations/callbacks use them, preserve required final callbacks, close media bindings, then complete backend teardown before releasing client file service, cache storage or callback objects. Preserve meaningful driver-shutdown order; do not require protocol SessionClose in the common interface. `Audio::remove` presently clears maps and shuts Miles down before final cache deletion (around 1380–1455); this is evidence to preserve and audit, not proof that every asynchronously adapted shutdown is safe. Host crash is a terminal backend failure with unknown outstanding operation outcomes; never replay side-effecting calls to manufacture continuity.

## Bink is the replacement escape test

A `void *nativeDriver()` on the common backend interface defeats replaceability. It either leaks Miles back into game/media code or encourages casting a wire token into a pointer. Current Bink setup calls `BinkSoundUseMiles` only for a non-null pointer, but passing null to bypass that call is not evidence of equivalent audio.

Use a narrow media integration adapter selected with the renderer and media implementation, with explicit attach/detach lifetime. For original 32-bit Miles/Bink, the real driver and consuming Bink code must be co-located; moving Bink media operations across a boundary is outside the 61-opcode audio schema. A native x64 Miles/Bink combination can bind locally if actually available and compatible. An alternative renderer needs a validated Bink output path or replacement media integration that preserves timing/output. No generic exported driver capability can substitute for that work. Do not promise whole-client removability until this path is implemented and validated.

## Migration and deletion criterion

1. Label the pipe composition temporary and identify its removal goal. Add the typed startup-only client interface in a new candidate, with a bridge adapter as the sole owner of frame/protocol types. Preserve all frozen evidence. Type-check a second in-process fake implementation to prove source independence only; it proves no audio fidelity.
2. Inventory direct SDK types/calls across clientAudio, its precompiled-header exposure, Sample classes, SoundObject3d and Bink. Maintain compile/link reachability separately from lexical enumeration. Route the actual current startup client through the typed seam and retain its observed checks.
3. Add playback contract methods only as each actual Audio call site is migrated with explicit image ownership, borrowed stream aliases, error behavior and callback execution rules. Keep SDK ABI shims and wire API-MAP behind the bridge adapter. Contract checks should discriminate ordering, stale identities, reentrant callbacks, failed assignments and shutdown, rather than merely assert vtable entries exist.
4. Resolve the media binding and callback executor using permitted source/compile evidence and later explicitly authorized runtime validation. Do not expand runtime scope on the basis of this document.
5. Install a candidate native/alternative implementation behind the same client contract. Validate the full feature/behavior matrix, including streams, looping/seek, 2D/3D/spatial/reverb, premix/service behavior, buffered sound/music, TreeFile, callback ordering, media synchronization and error/shutdown paths. No stub or silently missing feature satisfies full fidelity.
6. Delete the bridge when the selected replacement passes that validation and a build/package exclusion check succeeds with every pipe/host/protocol source, executable, DLL deployment hook and configuration dependency removed. Ordinary Audio/Sound policy and client-facing game behavior should not change in that deletion. Build selection and backend/media adapter removal may change. Keep historical reports as archival evidence, not live runtime dependencies.

## Likely naive-vtable failures

- `execute(opcode, void*, bytes)` is the same SDK/protocol facade with indirect calls.
- Common interface includes `MilesWire::Handle`, `Result.transport_status`, lock lease, upload tokens or raw HSAMPLE/HDIGDRIVER.
- A borrowed stream sample becomes an owned handle and is independently released; reused handles accept delayed EOS for a different object.
- Every input pointer is assumed valid only until method return, or every input is retained forever without a defined memory/failure policy.
- Completion delivery is moved to the next frame, or into the I/O thread, without proving callback timing and game callback restrictions.
- A method-level mutex stands in for vendor lock/start batching, deadlocking on reverse file I/O or admitting another logical caller during the protected batch.
- A generic destructor closes transport before final file/callback work finishes, or promises callback quiescence after stop rather than after an explicit barrier.
- Bink takes a supposedly opaque driver cast back to a pointer; null-driver fallback is called equivalent without evidence.
- A native backend is forced to implement host launch, Hello, BufferSeal and SessionClose solely because the bridge schema was treated as the audio contract.
- The startup-only adapter is described as proof that all playback can already be swapped. It is an architectural first step; the hardest semantic work remains open.
