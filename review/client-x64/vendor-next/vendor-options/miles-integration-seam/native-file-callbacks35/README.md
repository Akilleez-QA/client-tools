# Native-shaped file callback interface proposal35

`ClientMilesFileCallbacks.h` exposes four plain callback typedefs and `ClientMiles::set_file_callbacks`. It deliberately does not include the existing modern-STL ClientMiles startup header. The only public data types are fixed-width integers, native-width `uintptr_t`, pointers and explicit `__stdcall` callback types. The facade function itself follows the existing ordinary C++ ClientMiles convention; the private vendor call uses the SDK's `AILCALL`. Callback identity, result bits, null pointer arguments and the four-pointer order pass straight through without casts, normalization or registration tokens.

Possessed header SHA-256 `966e1e81046851295079e9709f9f358286c823e4403ec6b0ca972b5059725e6e`: lines 5222–5242 declare open as `U32 (AILCALLBACK *)(MSS_FILE const *, UINTa *)`, close as `void (AILCALLBACK *)(UINTa)`, seek as `S32 (AILCALLBACK *)(UINTa,S32,U32)`, and read as `U32 (AILCALLBACK *)(UINTa,void *,U32)`. Windows `MSS_FILE` is `char`; normal Windows `AILCALLBACK` and `AILCALL` are `__stdcall`; Win64 `UINTa` is `unsigned __int64`. The private TU asserts actual type identity for all four callback typedefs and the vendor registration signature. No compiler has run for this proposal; compatibility is an intended compile gate, not yet a result.

Original49d0 Audio declarations at lines 234–237 have these same four shapes, and line1293 installs them before digital-driver opening. The original callbacks use the shared legacy once/TLS prologue. Frozen29 extracts their operation bodies into `ClientAudioFileCallbacks` while preserving those original SDK trampolines and registration behavior. The probe checks original callback-shaped declarations can enter this facade beside the vendor-free common-operation header under the engine include environment; it does not replace or execute Audio.

For direct native selection, installation merely forwards the callback pointers. When Miles invokes them, they run synchronously on the thread Miles chose, with the same original trampoline TLS behavior. This wrapper neither moves work to the installer's thread nor installs TLS. Retain callback code, file-map state, TreeFile and supporting engine lifetime until vendor shutdown has returned and quiescence is proved; returning from registration or setting null callbacks is not asserted to prove quiescence. No pointer ownership or destructor crosses this header.

For later pipe selection, callback addresses must remain local. SessionFiles34 represents the trusted owner's session-wide callback table before driver/file creation; it is not fabricated protocol registration. Actual original32 host callbacks will use the private reverse-I/O adapter. Client file operations must enter the dedicated engine worker with already-installed TLS and serialization, using frozen29 common operations, not the legacy SDK trampolines that could install TLS again. The receiver remains independent of blocking reads. The table, worker and request/callback pins must survive vendor shutdown, late closes and partial-install cleanup; zero pins alone leave `vendorTerminationUnproven` true.

This creates an explicit thread-context difference between direct and pipe selection. Inspected production file I/O permits the dedicated TLS worker, but causal/background reentry, fatal-path behavior, timing and shutdown fidelity remain unmeasured. This proposal does not bridge SDK callbacks to the worker, alter Coordinator34, ship callback pointers/handles on the wire, or adopt the interface into product Audio.
