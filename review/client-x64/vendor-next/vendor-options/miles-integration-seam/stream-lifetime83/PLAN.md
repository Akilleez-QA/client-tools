## Real host path

Backend adds only AIL_open_stream, AIL_stream_sample_handle and AIL_close_stream cases, retaining existing77 non-lifetime stream/control dispatch. Reject callback/reserved/output mask, bytes payload, resource and unused values before effect. Open requires a present, bounded, terminal-NUL filename with no interior NUL; close/getter require no text. Host's existing codec::decodeCall establishes canonical span/frame layout before Backend; Backend repeats bounds/NUL checks before reading. StreamMem is decoded by memcpy of all32 bits into actual S32 with a size assertion, not narrowing unsigned conversion. Running lifecycle and exact Driver/Stream resolution precede native calls.

Open reserves a Stream row with live Driver parent before AIL_open_stream. One member Reservation, pending HSTREAM and pending flag retain the serialized transaction in the already heap-retained Backend. On confirmed nonnull native return publish cannot allocate and transfers identity to registry before clearing pending state; confirmed null cancels only unpublished reservation and remains a normal null result. An unexpected C++ unwind/publication failure leaves pending state and prevents any subsequent Backend execution. Actual host catches failures and invokes its existing terminal path; it does not delete Backend. No compensating close or fake null. This does not catch SEH, survive a process crash, or promise knowledge of an SDK ownership result never returned. A published stream remains registered if later reply/transport work fails.

Getter resolves live Stream and calls actual AIL_stream_sample_handle exactly once. Null preserves null; nonnull uses existing stable insertBorrowed, with no independent ownership/release. Every success echoes requested parent kind/slot/generation in values0–2. Repeated different nonnull native alias for the same parent is terminally refused as the existing selected stability restriction, not claimed universal SDK behavior. Insertion can allocate; failure retains the owned parent and returns no ordinary reply.

Close saves native pointer, beginClose occurs before AIL_close_stream, and retire follows confirmed return. During close Stream and BorrowedSample resolve refuse ordinary controls. No callback worker/Endpoint is stopped: existing admitted file thunks synchronously consume/copy/ACK, and existing client LiveChannel returned join precedes successful Core close/row erasure. Unknown close outcome retains closing state and host terminates normal processing. Native declarations do not prove EOS/background quiescence; no EOS registration exists in this candidate. This is not Audio streaming or normal teardown proof.

## Registry changes and invalidation

reserve now permits Stream only with resolvable Driver parent. resolve(Stream) checks that parent; resolve(BorrowedSample) checks Stream recursively. Parentless insert(Stream) now refuses rather than bypassing the reservation contract. Source search of actual77 candidate finds no production insert(Stream) consumer; older transport/host preflight fixtures do use it and would need explicit typed-parent setup if later selected. Those historical fixtures were NOT edited, reused or silently asserted compatible.

Driver retirement scans live(state1), closing(state2) and reserved(state4) OwnedSample/Stream children with exact matching parent identity. For each Stream it first scans/retires its live BorrowedSample descendants, then retires the stream. Direct Stream retirement performs the same alias scan. No vector growth, dynamic allocation, SDK cleanup or recursive object destructor occurs during this bounded iteration. Only identity state/generation is retired. Existing File and legacy OwnedSample insertion contracts stay unchanged.

Retiring a reserved child advances generation (or permanently exhausts it at generationLimit) while its Reservation still holds old identity. A later publish fails; cancel/destructor compares state, kind and generation and cannot cancel a new reservation reusing that slot. The token still must not outlive its registry. Test scenario explicitly reuses the invalidated slot before the old token destructor, then publishes the new reservation. This tests actual generation guards rather than a separate model. Header comment now accurately admits allocation in reserve/insert/insertBorrowed, while publish/cancel/retire do not allocate.
