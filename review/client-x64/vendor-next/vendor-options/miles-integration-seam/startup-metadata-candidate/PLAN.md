# Startup metadata candidate — prospective scope

Read the actual Audio.cpp startup sequence and preference setters, API-MAP, and the private original Mss.h declarations. This is a separate experimental component; no frozen component or product file changes.

Supported calls: get preference IDs 1 (mixer channels) and 42 (fragment count); set preference ID 42 to the client's actual values 16 or 64; copied last-error text; redist-directory with one complete NUL-terminated input string; speaker configuration only with a live Driver, mask 8, three null outputs and a valid channel-spec output. The speaker return pointer is ignored, never serialized. Unsupported IDs, presence masks, stray fields and malformed text spans reject before vendor dispatch. The current caller has no generic preference interface.

SINTa is signed 32-bit in the original x86 SDK. Wire return bits retain that representation, then explicitly sign-extend for the client. A portable preparation helper rejects out-of-range client values without truncation. Negative/min/max values are codec tests only, not arbitrary preference writes.

Returned strings are copied immediately into owned storage. Result.null_mask bit 0 denotes a null text return; null has no payload, while nonnull empty has one NUL byte. This assignment is local to these text-returning opcodes. Returned pointers are trusted SDK C strings, not untrusted readable-memory spans. The scan stops at the transport's maximum available text extent; longer text is an explicit transport failure after the real call, not a fabricated vendor result or a rollback claim. Allocation failure propagates. No raw pointer crosses the protocol.

Pure native x86/x64 Debug/Release checks cover signed boundaries, null/empty/nonempty text ownership, exact encoded bytes, output presence and rejection before dispatch. Genuine host builds are x86 only and link the original import library. If run, direct and dispatched calls use the same original DLL and are explicitly a same-vendor oracle: save preference42, set known16/64, compare actual return and readback, restore saved value directly even on failure. Read preference1, copy last-error strings before another SDK call, set a valid directory without file writes, and compare speaker channel-spec on a genuine idle driver. Fixture startup/shutdown and direct SDK control calls are separate from this component. No playback, callbacks, streams, malformed media, engine allocator or engine teardown.

A deterministic private mutation changes the fragment-count setter's valid16 value to64. Readback and previous-value expectations must fail while preferences are restored and normal shutdown completes. The original component remains unchanged. Genuine execution uses the existing private original DLL and isolated Wine/null-sink route, unchanged audio defaults. Receipt-style input/output hashes bind native binaries; no generic infrastructure expansion. No commits, pushes, SDK/media/binary publication or full-fidelity claim.
