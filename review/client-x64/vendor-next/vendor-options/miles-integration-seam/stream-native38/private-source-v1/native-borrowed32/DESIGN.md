# Common sample source handle: proposal32

Use one opaque `Sample *HSAMPLE` for Miles sample operations. `allocate_sample_handle` returns an owned allocation; `release_sample_handle` accepts only that owned allocation. `stream_sample_handle` returns a borrowed sample whose lifetime is bounded by its parent stream. Copies alias identities; neither pointer type nor copying transfers ownership. The caller must not use a sample after release, parent close or shutdown. Native delegates forward the SDK directly and cannot validate stale raw vendor pointers. This is a source facade, not a vendor ABI declaration or RAII ownership scheme.

The original7.2a header declares `AIL_stream_sample_handle` at5166 as HSAMPLE from HSTREAM. Current Audio.cpp uses that result in exactly five shared controls: set_sample_volume_levels3211, set_sample_reverb_levels3212, set_sample_playback_rate3260, sample_volume_levels3305 and sample_playback_rate3334. Keep those existing function names/signatures. Do not add parallel borrowed variants or require caller casts. Other operations retain the owned-sample precondition in this supported subset; this does not claim the SDK itself forbids every other operation on a stream sample.

Patch01 changes three public headers' type/comment surface and adds one direct native stream delegate with actual-header signature checks. Existing native sample27 and playback28 delegates remain source unchanged and compile against the common opaque type when the whole candidate is composed. A source-compatible call shape is preserved, but changing the C++ opaque pointee changes mangled symbols: rebuild all facade and consumer translation units together; do not mix old owned-only objects with new ones. This proposal has no native or portable compile evidence yet.

Patch02 mechanically migrates the existing repaired private client29 implementation as captured by successful31 from its internal OwnedSample struct name to Sample. Its container still creates only owned proxies, and ownedSample still searches only that owned container. This avoids a public-header/private-definition type mismatch; it does NOT implement streams, borrowed proxies or any newly enabled control. The private wire enum OwnedSample remains2, BorrowedSample remains4. No lifetime or transport behavior changes are claimed for the mechanical rename. The successful31 owned-only binary/receipt remains immutable evidence for its original type, not proof of this source revision.

Reuse existing host machinery rather than duplicate it: RegistryResolver resolves only permitted resource kinds; host_dispatch already permits OwnedSample|BorrowedSample for all five actual stream controls. ResourceRegistry::insertBorrowed caches one alias per live Stream parent and rejects silently replacing its native target. resolve checks the parent's live slot/generation; beginClose makes the parent unavailable, and retire(stream) invalidates borrowed alias generations. Borrowed samples cannot beginClose/retire independently. The current composed31 Backend still has no stream open/close/sample-handle admission path; these existing helpers alone do not establish operational stream support.

Future private stream composition must own one reclaimable Sample proxy per stream alias, validate selected Session plus exact wire kind/parent/generation, and reject borrowed release before exchange and at the host. Reserve local tracking before a remote operation can create obligations; retain stream ownership if alias publication fails. Repeated stream_sample_handle on the same live parent reuses its alias; a changed native target is an explicit failure/invalidation problem, never silent rebinding. On confirmed close, retire the host parent/alias and destroy its local alias proxy; on confirmed shutdown clear both owned and stream-owned proxies. Known refusal preserves prior valid state; unknown close/shutdown poisons the Session and retains local tracking until abandonment, without replay or claiming vendor cleanup. Reclaim proxies with their parent, not indefinite tombstones. A stale raw pointer after close is invalid API use; pointer-address reuse does not provide an ABA guarantee. Private wire generations and session binding provide their separate protections.

Callback ordering/quiescence, file executor integration, stream startup/close runtime, borrowed controls under real decoding/playback, binary compatibility and native Miles64 linking/runtime remain unproved. No product, prior snapshot or runtime artifact is edited. No gates are run in this task; a compile recipe and exact object/import checks can follow parent source review.
