# Session file admission successor34

This isolated Coordinator successor permits a trusted owner to register the global file callback table before any driver or file exists: `registerSessionFiles(session, registration)`. Scope is private state, never wire input. It creates no synthetic handle and leaves the existing `registerCallback` resource validation intact.

One SessionFiles registration shares the existing monotonic registration ID space, registration quota, callback quota, callback sequence limits, ACK accounting and close frontiers. Any active native admission pins the session registration, including an admission with an empty resource list before driver creation. ResourceScoped registrations keep their original resource-specific pins and closing-resource checks. Session close requires Draining or Failed; Draining closes ordinary intake while already admitted and cleanup work can still hold pins. Failed continues to retain pins and accept actual late observations without permitting new native admissions.

Portable validation passed with `g++ -std=c++11 -Wall -Wextra -Werror -pedantic`: all 87 unchanged original Coordinator checks and 92 new SessionFiles checks. The new checks cover pre-driver registration and causal callback bookkeeping, singleton/ID uniqueness, shared limits, registration/completion/ACK replay rejection, stale sessions, draining, cleanup, failure, request/callback pins and out-of-order ACK frontiers. Raw commands and logs are in `portable-v1`; `resource_regression_test.cpp` is byte-identical to the original test. No compiler diagnostics occurred.

`vendorTerminationUnproven` remains true, including after all observed pins reach zero. This model supplies no vendor termination proof. It is not a wire replay filter: duplicate callback intake must still be rejected by the existing transport/owner path before observation admission. The pre-driver test models FileOpen using an empty-resource admission and causal callback; it executes no decoded FileOpen, engine operation, SDK call or transport.

Next integration must have the trusted session owner allocate this registration before vendor callback installation, retain the real worker and callback-table owner through vendor shutdown, and associate incoming file callbacks with that already-owned registration. It must preserve actual causal identity and use the existing admission/pin/frontier contracts rather than infer scope from a wire handle. FileOpen result binding, worker completion, reply ACK, partial-install cleanup and termination evidence still require composition. There is no dispatcher hookup, worker adoption, native compile, VM action or engine runtime in this successor. The original Coordinator and product checkout are untouched.
