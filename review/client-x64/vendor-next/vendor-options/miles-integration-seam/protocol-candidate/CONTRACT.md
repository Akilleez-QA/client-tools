# Protocol candidate: one client, one original-vendor host

Experimental schema only; no transport, host, shim, production edits or adoption. All61 reviewed function names have fixed opcodes and field mappings in API-MAP.md. AIL_MSS_version is a separate host diagnostic macro operation; it is not an export. Header layout assertions pass GCC32/64 syntax checks; native MSVC ABI/function-signature verification remains required. Fieldwise little-endian codecs are required even though struct offsets are fixed. No pointers, SDK structs, C++ bool/size_t or native handles travel on the wire.

## Framing, ownership and lifetime

Header bytes includes header+fixed payload+trailing spans, bounded1MiB. Every span validates offset<=bytes and length<=bytes-offset; metadata regions cannot be addressed as image data. Sequence IDs cannot wrap within a session. Reserved fields zero; exact version/opcode/size required. A disconnected session fails as transport, never supplies fake vendor success/error values. No retries of side-effecting calls after unknown outcome. Dedicated ordered request/result and callback directions prevent an unsolicited event from being parsed as a response. A lane is a session-local client thread identity, not an OS pointer; causal_request names the request that caused a reverse call, or0 for genuinely unsolicited activity.

Handle identity is kind+slot+generation; host owns real driver/sample/stream/file addresses. Slot0/null is allzero; live generations start1 and never wrap/reuse a retired generation. Proxy address is local storage, not token bits cast to HSAMPLE. Copying a proxy preserves identity; arbitrary/unregistered pointer is an adapter error, not an instruction to dereference host memory. No ordinary vendor behavior is implemented by returning a transport error.

Create publishes registry entry before vendor can emit an event; client callback registration and proxy identity must be available before dispatching that event. Actual callback order relative to create/start response is retained by event sequence, not guessed. Release/close transitions LIVE→CLOSING, runs actual vendor operation, records callbacks it causes, and retires only after callbacks no longer use the resource. Return from stop is not equivalent to callback quiescence. Generation validation must distinguish historical queued events from current objects rather than dropping all events after stop.

Repeated stream_sample_handle returns the same borrowed proxy for the same actual sample+stream generation. It can be passed to volume/rate/reverb etc.; it cannot be independently freed by release_sample_handle. Stream close invalidates aliases after vendor completion and callback barrier. Driver shutdown retires dependents in the vendor's actual order. If vendor can change the stream's sample alias, create a new identity rather than silently retarget an outstanding proxy; this needs real stream evidence.

## Image/pointer seams requiring explicit adapters

1. **AIL_set_sample_file**: Audio.cpp:2925 already has SampleCacheEntry.m_fileSize beside m_sampleRawData. Experimental source call would be `setSampleFileSized(sample, image, entry.m_fileSize, block)`. Check nonnegative size before upload. This is the minimal call-site addition; do not infer total file extent from WAV headers. It preserves actual AIL_set_sample_file in host, not replace it with named-file API.
2. **AIL_WAV_info**: Audio.cpp:3710 already holds fileSize used to allocate/read fileImage. `wavInfoSized(image, fileSize, &info)` supplies its exact span. SoundInfo transports scalars and nullable checked offsets for data_ptr/initial_ptr; validate the data extent as well as pointer offset. Translate offsets back into the same still-live client file image only when in bounds. If vendor returns an out-of-image pointer, do not fabricate a mapping; preserve failure as unresolved compatibility evidence. Current caller consumes scalar fields, but a general shim cannot claim pointer semantics it has not reproduced.
3. **AIL_speaker_configuration**: current caller requests only channel_spec and ignores returned vector pointer. Adapter can explicitly request just that field; preserve all other optional scalar outputs in schema. Returning a fake vector pointer is forbidden. Supporting the returned MSSVECTOR3D array requires vendor-documented element count/lifetime and a client shadow invalidation contract; this remains unresolved. Do not infer array count from channel spec alone.
4. **AIL_last_error / set_redist_directory**: nullable returned strings are copied before host storage can change. Client shim owns shadow storage, with explicit per-call/per-thread lifetime to be established from the actual SDK contract. Do not silently truncate to frame capacity: chunk or explicit negotiated string bound with truthful failure, never change diagnostic text. Preference SINTa is a separate scalar seam: only observed scalar preference IDs, checked signed32 on host, sign-extended return; pointer-valued preferences require new reviewed handling.

BufferBegin/Chunk/Seal permits U32-sized payloads without a giant one-message cap. Exact immutable byte count, overlap/completeness checks and no uninitialized gaps. set_named_sample_file/file_type already carry sizes. Uploads own storage until all actual vendor references end; releasing transfer bytes when RPC returns is wrong. Reassignment/failure lifetime must be measured against original API; conservatively retaining to sample destruction prevents dangling data but may increase memory and is not yet an accepted final lifetime policy. No fabricated huge allocations are needed to test arithmetic rules.

## Callbacks, file I/O and lock gates

Callbacks remain registered locally under64-bit registration tokens; previous-callback return maps to original client function, not host trampoline. Replacement/unregister returns actual previous registration identity; in-flight old events retain their registration until drained. EOS events have resource+registration+event sequence. No coalescing or frame batching. Acknowledgement means local callback returned, not that original timing was preserved. A callback's permitted reentrant AIL calls must match real API restrictions, not invoke arbitrary recursive dispatch.

File reverse operations: Open(text)->U32 result + File identity; Close(File)->void; Seek(File,S32 offset,U32 type)->S32; Read(File,U32 requested)->U32 actual + exact bytes. Host copies read result into vendor buffer only after checking actual<=requested. Host stores returned local file identities, never client UINTa/AbstractFile pointers. Null success handles are not inferred: real Audio starts s_nextFileHandle at0, so open status is authoritative. Preserve TreeFile mount/priority/seek behavior and original encoding. Audio fileOpen callback installs PerThreadData on a nonmain thread: moving it to any receiver thread without corresponding engine initialization is not valid.

A waiting client call must service causally related reverse I/O while preserving the engine's thread ownership; it must not hold a nonreentrant transport mutex while vendor waits for callback. Unsolicited file I/O requires its own declared initialized callback thread route. Do not recursively process unrelated game commands while waiting. On the host, reads/callback replies require an I/O dispatcher independent of a blocked vendor execution lane.

AIL_lock/unlock are real vendor operations, not a proxy mutex or best-effort flag. Each mapped client lane needs stable original-host execution/thread context; hold/release must run on the same host lane, including nesting behavior only if confirmed by original API. While locked, callback replies must still transit independently. Never replay lock on a different thread or acknowledge it before vendor acquires it. Miles header documents startup-thread interaction; one global worker plus blocking reverse callback can deadlock, and spawning a worker per request changes affinity. The exact lane policy therefore remains a critical runtime trace gate. This schema carries lanes/causality; it does NOT prove a safe dispatcher exists.

Bink must share the real driver in the same host. The numeric driver proxy returned to64-bit Audio cannot be fed into original Bink. Video command/image transport is outside this61-call schema and remains required before whole-client original-media acceptance.

## Required discrimination before implementation selection

Use actual-header native type checks for all function signatures and frame layouts; test resource alias/release ordering with real vendor, callback replacement return, file-open handle0, reentrant seek/read and nested ordinary lock sequences only where documented. Exercise the actual engine Sound2d slice from PLAN, not registry tests alone. Preserve callback/thread/PCM differences and do not invent a timing tolerance. Unresolved speaker-pointer lifetime, image-return offsets, vendor buffer lifetime and thread-lock affinity are explicit design blockers, not permission for stub exports.

## Review correction: logical lock ownership

A single host OS thread is insufficient even if it calls real AIL_lock: its recursive vendor lock could accidentally admit client laneB while laneA owns the lock. Header.lock_lease is0 outside an epoch; successful Lock returns a new lease in result.value0/1 (low/high). Dispatcher admission must bind lease to owner lane and verified recursion depth; another client lane cannot borrow it merely because host execution uses the same OS thread. Unlock consumes exactly that lane/lease/depth and only releases waiting unrelated work after vendor release. This does not coalesce Audio::alter or reorder setters. Reverse TreeFile responses continue over independent response routing while the lease exists; they are not unrelated vendor API admissions. Whether any legitimate callback AIL reentry needs owner-lane admission remains to be traced—do not universally transfer the lease to callback threads. This is a required invariant/design gate, not a proposed general-purpose scheduler.

On x64 Mss.h's Windows version macro selects MSS64.DLL (line505); there is no genuine64-bit runtime resource in this strategy. The explicit SessionVersion adapter asks the32-bit original host for its actual original runtime version, rather than letting the x64 macro attempt its default library or returning an empty string.
