## Present facts and bounded next patch

This is current missing implementation; it is not evidence of a currently exercised stream ownership failure. PipeCore already declares/serializes these three calls, and its stream rows cannot become live through the selected host today. Do not characterize speculative queued EOS reuse as a reproduced bug: both EOS public operations remain missing.

The next patch should touch only the existing registry, Backend lifetime cases, and any necessary request/response checks; retain the current public header and one Session/Runtime path. No second resource map, token namespace or callback framework. It can establish source-level open/getter/close semantics under the existing no-EOS-registration boundary; it must not claim real Audio streaming until the separately missing EOS/file/root/TLS/shutdown obligations are satisfied.

1. **Reserve before open.** Extend resource_registry.h:88–116 to permit Stream with a live Driver parent, matching OwnedSample's parent validation. Allocation and native-argument validation must finish before AIL_open_stream. Check lifecycle, exact Driver target, filename payload framing and terminal NUL/no interior NUL, unused fields and signed stream_mem. Obtain native driver through resolve, decode the signed value without narrowing ambiguity, reserve tracking, call the actual SDK, then publish into the existing row without allocation. Native null cancels only the unpublished reservation and is a normal null result. If native ownership may exist but the outcome/publication is uncertain, fail terminally while retaining tracking/native state; do not silently cancel a possibly owned stream, invent null, or issue compensating close. Preserve client Core's preallocated row and uncertain-result retention.

2. **Make the entire parent chain valid.** Stream resolve must check its Driver parent, and BorrowedSample resolve must still check its Stream parent. Driver retirement must invalidate live/closing/reserved Stream children AND their BorrowedSample descendants, in addition to OwnedSample children. Do not add Stream to the existing driver loop and call retireEntry alone: that would skip stream's alias cascade. Implement explicit bounded iteration within the one registry, without allocating during retirement. Reserved tokens must remain safe to cancel after invalidation and never outlive the registry. Registry invalidation records identity retirement; it is not vendor cleanup and cannot substitute for native close/shutdown ordering.

3. **Borrow the sample without transferring ownership.** Validate the live Stream and exact getter fields. Call AIL_stream_sample_handle once. A null result stays null and still echoes the exact requested Stream identity. For nonnull, existing insertBorrowed:145–159 returns the stable wire alias for the same parent/native sample and rejects retargeting. Client Core's embedded borrowed proxy and validator already enforce this stability, exact parent echo and uniqueness before returned/join. Do not release/delete the returned sample separately. If first alias insertion allocates and fails, retain the parent and fail the session, without manufacturing a null return. Preallocating an alias slot is optional only if justified; the getter does not acquire ownership. The SDK declaration does not itself guarantee repeated getter stability: current fixed-alias behavior is an explicit selected restriction that needs evidence before broad native-equivalence claims.

4. **Close around the actual effect.** Resolve and retain the native Stream pointer, validate all fields, then beginClose before SDK entry. Closing must reject new ordinary stream/borrowed control lookups. Keep the owner/callback/file-operation state alive while AIL_close_stream runs. Only a confirmed return and the required callback/ACK settlement allow parent/alias retirement and a normal reply; uncertainty keeps closing state and terminates further normal work. On the client, LiveChannel.cpp:91–99 already validates owner/context before Runtime::returned; Core close_stream then erases the row only after request succeeds. Preserve that order. A future EOS event must hold generation/registration-specific identity until delivery or explicit retirement, not merely a recyclable raw proxy address.

## Close and callback evidence that is still required

Mss.h:5162–5166 declares the open/close/getter signatures; :5082 and :5190 establish the typed stream callback and previous-callback registration return. These declarations do not prove close waits for every callback, that unregister cancels queued events, that callbacks cannot reenter, or that shutdown is quiescent. Do not infer such guarantees from the host link or the SDK stream struct's internal fields.

The existing actual close admission must allow file callbacks needed by native close to finish; do not stop the file worker/channel before invoking SDK close or wait for an ACK while preventing the worker that produces it. The selected Runtime return join covers its admitted file operations, not nonexistent EOS delivery. Before enabling EOS, specify which queued callbacks must be delivered, suppressed or joined across close, how previous game callbacks are returned, and which actual vendor guarantee or explicitly supported restriction establishes the barrier. If that evidence is unavailable, retain the EOS limitation rather than making source-only close a claim of full native semantics. A discriminating later test queues an old-generation event before close, reaches the defined barrier, creates a new stream, and verifies the event cannot select the new row. Calling a freed native handle is not a valid equivalence test.

## Actual Audio and removability

Product Audio.cpp:605 opens with driver/path/stream_mem0 and stores only nonnull handles. :3072 registers EOS before start. :3211–3212,3260,3305,3334 obtains the underlying sample for precisely the five controls now admitted. :3367 closes and immediately nulls its stored handle; :4783 onward compares callback HSTREAM identity against the map and mutates sound state. These are the concrete behaviors the completed adapter must support. A file-only stream lifetime slice cannot stand in for EOS registration/delivery.

The public boundary is plain and shares the possessed SDK's opaque tags, so selected native70 can implement the same handle/callback signatures without a callback thunk. That is a useful removable implementation boundary, not an unchanged-source replacement of today's Audio.cpp. Audio still uses AIL_* names, SDK constants/types, MSS_version macro and full speaker-configuration call. ClientMiles uses namespaced names/constants, a SampleInformation projection and speaker_configuration_spec; initial Audio adoption requires deliberate naming/type/macro adaptations. Once adopted consistently, switching the implementations can leave those call sites fixed; replacing it with raw SDK calls without the thin native adapter would undo those adaptations. A future Miles64 SDK with different tags/types or macro contract must be checked independently; current SDK assertions cannot promise that future compatibility.

The more material adoption changes are currently outside the plain signatures: genuine private root/reporter ownership, callback-module lifetime, normal shutdown/join, image extent/retention, and locks. File79 establishes a concrete pending interaction: unchanged Audio callbacks can reinstall TLS on an already initialized EngineFileWorker thread. The dormant29 common-operation extraction supplies an existing direction, but selecting typed admitted wrappers is an Audio integration choice, not permission for the adapter to silently substitute different callbacks. A backend swap must preserve the intended callback bootstrap policy without scattering pipe-specific scheduling branches through Audio. Keep that selection at the reviewed Audio callback/composition boundary. The one-time nonnull file-registration restriction fits the observed install call but is not native replacement/reset support.

Thus the next patch should complete the three stream lifetime cases and parent/alias identity handling under explicit current restrictions. It should not expand into EOS, global locking, TLS redesign, metadata or normal teardown, and its eventual tests/compile result must state that operational Audio streaming remains blocked on those separate pieces.
