# Prospective tests-only composition49

Read callback-composition46/REVIEW-blind.md first. This successor preserves46's production source, frozen inputs and successful result. No compiler, portable execution, native, SDK, engine or product workload has run for49. Parent review and a separate portable gate are required.

Exactly two candidate files change: portable_job.cpp (explicitly test-only Windows worker/job substitution) and callback-control45/tests.cpp. The runner retains46's strict Clang ASan/UBSan flags, bounded first build/run, exclusive evidence directory and before/after freeze checks; adds an explicit --approved-portable gate and three new scenario markers. The original twenty scenario markers remain. There are no production changes or implicit incorporation of47's guard.

Precommitted oracles:

1. A's actual scripted read, seek and close reject any handle whose value is not exactly zero, before performing the operation. Existing two-session read/seek/close reply assertions now fail if forwarding changes zero to another value. B's wide-handle checks remain unchanged. This strengthens the existing scenario rather than counting it again.
2. A failed open returns status zero while writing nonzero local output 0x7654. A fixture with exactly one file slot performs two failed opens, each with all-zero returned wire resource and no coordinator failure; each ACK releases its operation. A following successful open and close must work with that same one-slot capacity. This discriminates false publication/reservation leakage without adding owner introspection or assuming the contents of a hidden resource identity. Status-zero preservation/no publication is tested through the real selected-services, Invocation, owner and codec path. The fixture's optional fileCapacity only configures its existing owner constructor.
3. Forward return is observed after enqueue but before pump: callback count is unchanged and reply absent. The command remains ReturnedWaiting with one request pin and one callback pin. Pump then executes the callback and makes the reply available, but both pins remain until the real reply-queued/consumed ACK. Only then may the command settle and be consumed. This is a controlled sequential Pending schedule, not concurrent native scheduling evidence.
4. A standalone actual Invocation holds selected services and a separate lifetime context. No Fixture or SessionFileOwner exists for this scenario. Drop external FileServices/table ownership, callback lifetime and context before execution. Weak pointers to all three must stay live through callback execution, then all expire when Invocation is destroyed. This isolates Invocation's copy ownership; it does not prove native queued-job ownership or callback code-module unloading safety.

Each new scenario runs once; failed-open two iterations are deliberately one more than the single available file slot, not a stress count. Existing tests are retained verbatim apart from the fixture parameter/declaration and added cases. No broad clearance is inferred from marker/assertion totals.

Compatibility: inherited portable-v1/native35_compat.h is unchanged. It preincludes the plain native callback header with local Windows/stdcall macros and undefines them before the remaining composition. This remains portable value evidence, not calling-convention evidence. Protocol remains46 Version1; unlike47, no forward pipe Version2 source is combined here. Production callbacks/files, runtime termination, engine Thread/Windows events, actual Endpoint transport and vendor quiescence remain outside scope.
