## 1. File callback type result and minimal delegate

The SDK's _WIN64 branch defines UINTa as unsigned __int64 at1253–1257, while U32/S32 are unsigned/signed int at1245–1250 and Windows AILCALLBACK is __stdcall at484–485. File callback declarations5222–5237 use those exact types. Plain51 FileHandle is uintptr_t, and its four callbacks match native35's declarations.

This is more than an equal-size argument: `native-file-callbacks35/native_file_callbacks.cpp:9–16` asserts `is_same<FileHandle,UINTa>`, signed/unsigned scalar equality, filename element equality and all four callback pointer types. The existing native35 direct-forwarder object receipt reports those assertions compiled on actual v120 AMD64; the current audit does not rerun it. The full plain51 header was added later, so a new implementation should repeat these assertions against that actual consolidated header.

Smallest direct implementation is the existing35 typed setter call relocated into60's separate SDK delegate TU, with52's ordinary public failure guard. It passes the four typed function pointers without function-pointer casts, handle conversion, boolean status conversion, slot table or host token registry. Caller file handle zero/nonzero and all status/seek bits remain the callback's native contract. Native64 direct mode does not use the helper's32-bit file tokens. A private guard cannot catch exceptions thrown later on another SDK thread; supplied file callbacks must obey the no-exception boundary contract.

Actual Audio starts Miles and then sets these four static callbacks once at1289–1293. The functions at3939 onward operate the engine's file map and contain their existing foreign-thread TLS installation pattern. This is not evidence of callback replacement/null-default behavior. For direct native mode, forwarding null/replacement would inherit whatever the SDK actually does; for the temporary helper, initial one-table policy remains separate. Do not claim a new default/null behavior or apply helper-only restrictions invisibly to the native reference.

## 2. EOS type mismatch and actual use

SDK AILSAMPLECB2519 receives SDK HSAMPLE; AILSTREAMCB5082 receives SDK HSTREAM. Plain callbacks receive distinct opaque `ClientMiles::Sample*` and `ClientMiles::OwnedStream*`. Their function-pointer types differ even though handle representations fit native pointers. Reinterpreting an AILSAMPLECB as plain SampleCallback (or the reverse) is not a valid implementation. The setter declarations4706–4708 and5190 return a native callback pointer; headers alone do not state when callbacks are selected relative to replacement.

Actual SWG source:

- Audio.cpp2878,2960 installs static 2D/3D EOS callbacks before start_sample;3072 installs stream callback before start_stream3085. Return values are ignored at these call sites. No replacement/null registration call is present in this Audio source.
- Audio.cpp4730–4789 callbacks search existing sample/stream maps by exact handle equality, mark PS_done and call Sound2::endOfSample. They do not merely signal a transport event. The private trampoline must pass the exact plain handle previously returned to Audio, without creating a different wrapper object identity.
- `Sound2.h:57` makes endOfSample virtual. `Sound2d.cpp:845–873` explicitly says certain Miles calls cannot be made there and defers release until the next alter; it sets flags/counters and invokes an optional game callback at862–866. `Sound3d.h:17` derives from Sound2d. This is concrete caller evidence against holding a registration mutex across game code or adding a synchronous self-join. It is not a general SDK quiescence specification, and the optional game callback remains arbitrary game code.
- Audio.cpp3350–3369 stops/ends samples, or closes a stream then nulls its handle. ReleaseSampleId3380–3407 calls stopSample first, releases native samples, then nulls/erases records. Stream map erase follows its close path. None of these call sites explicitly unregisters the callback before release/close.
- Audio.cpp1401–1416 clears maps before shutdown1437 after earlier shutdown work. This order does not by itself prove callbacks cannot race map removal. Existing AIL_lock/unlock wrappers4922/4928 are not evidence that each registration/close is fenced.
- Audio.cpp4437–4455 allocates/releases a temporary metadata sample without EOS registration, so not every owned sample necessarily has a callback.

The public51 promise is broader than observed SWG usage: return the previous **plain** callback, including null. Ignored returns in today's Audio cannot justify returning a native trampoline pointer or always returning null.

## 3. Smallest typed map/trampoline shape

One native-session-private sample list/map and one stream list/map, with typed rows. No public registry API, transport types, vendor user-data index or plugin framework. A row contains native handle, the exact plain handle, current plain callback (nullable), lifetime state, active trampoline count and a pin sufficient to keep the row/callback owner alive. A single native-signature sample trampoline and a single native-signature stream trampoline use their respective maps.

Allocation/open wrappers from60 must reserve a stable row before the SDK allocation/open can succeed, then publish its genuine native/plain handle without a new fallible allocation. An intrusive list with a preallocated row is adequate for this source-sized subset; a generic registry is unnecessary. Null native creation releases the unused row normally. All these handles must be created/released through the facade; borrowed stream samples remain ineligible for owned-sample EOS registration under51's selected subset. Lookup never claims arbitrary raw native handles are facade-owned.

Trampoline steps: lookup exact native handle under the small map mutex; acquire row/callback-lifetime pin and increment active count; snapshot plain callback and plain handle; unlock; invoke the typed plain callback; catch any exception into52's nonreturning boundary; then decrement active count/release pin under mutex. **No map mutex is held during SDK calls or game callback execution.** No generic nested dispatcher is added. The caller's existing thread/game-map serialization remains required; this adapter must not claim it made Audio's maps thread-safe.

Registration transaction: reserve any state before native setter, record prior plain pointer, and keep row pinned while setter executes. Return prior plain pointer only on a successfully completed registration transaction. The returned native previous pointer must be null or the known matching trampoline according to tracked prior native registration state. An unexpected foreign callback indicates broken exclusive ownership; fail terminally, retaining state after the possible setter effect. It cannot be translated into a previous plain callback by cast. Null unregister must call the native setter with null, and preserve prior plain callback return semantics. No vendor user-data slots are read or written: absence of such calls in Audio does not reserve slots against other SDK users.

## 4. Replacement and close timing prevent an unconditional implementation now

A simple current-pointer row is insufficient to reproduce all possible native replacement semantics. If the SDK captured the old native trampoline before a replacement but invokes it afterward, the same trampoline/handle pair cannot reveal which registration it belonged to. Changing the row before or after the setter merely chooses which possible callback timing is misrouted. An epoch stored only in the row does not solve this: no epoch arrives with the SDK callback. Holding a mutex across setter and callback is not a fix and can deadlock synchronous/reentrant delivery.

Similarly, after release/close, an old delayed callback carrying handleH cannot be distinguished from a new object allocated at the same native addressH. Retaining old rows or adding local generations does not attach a generation to that native argument. Safe reuse therefore needs producer quiescence guaranteed by release/close or another real documented SDK mechanism, not just local active==0. Active==0 means no trampoline currently entered; it does not prove none can enter later.

To implement without inventing timing, select and verify a bounded policy: first registration occurs before start; replacement/null change only when the object is actually quiescent; release/close excludes new producer callbacks and completes all in-flight deliveries before row reuse/destruction. The current SWG first-registration pattern fits the first condition, but source does not prove the quiescence conditions. Reentrant callback release is particularly important: The actual Sound2d implementation deliberately defers its own release, but invokes an optional game callback; the facade contract still cannot assume all callback code avoids reentrant object operations. Waiting for active==0 from inside that same active callback would self-deadlock. A design may defer row destruction until active reaches0, but must not fake synchronous native release completion or use a closed SDK handle afterward.

If runtime evidence instead shows callbacks can occur synchronously inside registration, replacement or close, the private state transition and callback-selection policy must explicitly support that documented order. Do not silently buffer/drop those callbacks, reroute them to a worker, or substitute a different callback. Those would change observable native behavior.

## Missing observations / concrete next work

1. Native64 setter previous-pointer behavior for first registration, replacement and null unregister; timing of synchronous/concurrent delivery relative to setter return.
2. Exact EOS/stream producer threads and whether they run under SDK locks; whether calling registration/release/close from the game callback is permitted and when such calls return.
3. Whether native release_sample_handle, close_stream and shutdown prevent future callbacks, wait for in-flight callbacks, and permit immediate native address reuse without stale delivery.
4. A root-selected lifecycle pin for callback code/game state and an explicit adoption transaction that routes native60 allocate/open/release/close/shutdown through these rows. Direct delegates alone are insufficient for EOS ownership.

These are missing observations, not claims of SDK bugs. Actual header checks can confirm typed trampolines, setter signatures and exact imports without executing the library; they cannot answer1–3. No native64 library is available, and no runtime gate is proposed here. No source implementation is authored in65 because the existing selected policy does not resolve these timing choices. File setter forwarding is independently type-unambiguous, but introducing it alone would not complete the native callback lifetime contract. The design is ready for a policy decision or genuine runtime evidence before code enabling these three names.
