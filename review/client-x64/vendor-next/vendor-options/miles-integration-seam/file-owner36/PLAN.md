# File owner36: prospective composition for review

Implement one private modern-STL `SessionFileOwner` beside the current transport owner, not another scheduler or lifecycle framework. Reuse Coordinator34, ResourceRegistry, file26 Request/Invocation/encoding and FileInvocationJob33. Keep native-shaped `ClientMiles::set_file_callbacks` public; the new owner registration is private. Frozen dependencies and product stay untouched. No native or real-engine runtime gate is part of this step.

**Ownership.** The session's existing outer owner retains a shared `FileSessionContext` containing the engine worker pointer and engine lifetime pin, plus the single SessionFiles registration ID. Start the worker with its existing checked readiness result before callback installation. Every job receives the same context pin. The outer owner outlives all jobs and retains the context in Failed; context destruction must not implicitly destroy or join a live worker. The session owner stores bounded operation records and file records; jobs hold context/file pins, not a shared pointer back to the owner that stores those jobs. Only the existing control thread mutates Coordinator, registry, records and reply publication. The receive loop stays nonblocking; the engine worker executes only the existing opaque callback jobs. All typed state and destruction remain in the modern TU.

**Reserve before FileOpen.** Allocate and retain a stable FileRecord, its shared ownership control block, in-place storage for the immutable Binding, and its PendingOperation record before queue submission. Insert the FileRecord's real address into the existing private ResourceRegistry as `File`, obtaining the generation-stamped identity before opening. This is an owner-side reservation: the identity is not sent and resolve must additionally require the FileRecord's Published state. It is never an invented engine file handle. The registry can store the record address even when the eventual local key is zero. A failed prequeue allocation or submit returns the reservation to the registry without any file operation. No registry API extension is needed if this file registry is private to the owner and every resolution checks record state.

The record has explicit states Reserved, OpenUnpublished, Published, ClosePending, ClosedAwaitingAck and Uncertain. On observed successful open, placement-construct Binding in the reserved storage using the genuine local key, then use an aliasing shared_ptr tied to the preallocated FileRecord ownership. This requires no second control-block allocation; only destroy Binding if it was constructed. Preserve raw open bits and local key zero. On observed failed open, retain the operation reply and release the unused registry reservation. On CallThrew/DispatchUncertain, keep the record and job as Uncertain: the actual side effect/key may be unknown. Never retry the open or synthesize a close.

**Publication storage is a concrete existing gap.** file26 `encodeCompletion` delegates to codec `encodeResult`, whose fresh Writer allocates its own vector and swaps it into the output. Reserving the owner's vector alone does NOT reserve encoding storage. The successor should add one narrow codec overload that accepts an already-sized result buffer and writes the same validated result representation without allocating, then expose that path to file26. Pre-size the operation's reply storage to `128 + requested read bytes` before worker submission (open/close/seek use128). Reuse existing field writers/validation and compare byte-for-byte with the existing encoder in portable tests; keep the old API behavior unchanged. Allocate the outbox node/retained-reply ownership before queue submission too. Completion only fills and publishes that already-owned node. If this codec change is declined, retaining a successful unpublished open on allocation failure is safe but does not satisfy the requested pre-reserved publication storage guarantee; do not pretend `vector::reserve` fixes it.

**Admission and completion.** The owner consumes a locally established association, decodes file26 Request against it, rejects stale/replayed reverse request IDs through the existing session replay path, checks genuine file liveness/state, and records the callback through the one trusted SessionFiles registration. Do not create a new game admission for a reverse callback while the causative admission is pending. Reserve all records before calling enqueueAdmitted; store the returned job without allocating. Retain the job while polling or reading completedInvocation. An observed Returned completion is not equivalent to vendor ACK. Preserve its operation record/reply until the existing reply-consumption ACK path acknowledges the exact Coordinator CallbackId; transmission alone does not advance the frontier. Complete the causal native admission only after its actual return and existing PendingCallback checks permit it.

For a known close, mark the file ClosePending before queueing and preserve the exact Binding for that job. Block later operations targeting that identity. Only an observed Returned close permits ClosedAwaitingAck; do not call close again if reply delivery fails. Keep a tombstone/operation record through ACK/replay retirement, then retire the identity without another engine close. A close that threw or whose dispatch is uncertain retains the binding/registry generation and context in Uncertain. Known successful opens whose replies cannot be published remain OpenUnpublished; cleanup close requires a later explicitly admitted cleanup path, not a destructor.

**Shutdown.** beginDrain stops ordinary native intake; callbacks from the still-installed vendor table and required cleanup remain processable under the accepted policy below. BeginClose on SessionFiles retains late callback observations and frontiers. Keep the worker/table/context through vendor shutdown and actual required close completion. Coordinator34 always returns vendorTerminationUnproven: neither zero pins nor a caught failure is proof to destroy the worker. No `readyToDestroy` boolean will replace missing external termination evidence. Until the session owner has an actual vendor termination/quiescence observation, preserve the context. After that observation and no retained work/files requiring close, call the existing drainAndJoin; false retains ownership/resources. Partial installation follows the same rule once callbacks may have become reachable.

**One missing routing decision before an operational end-to-end owner.** Current file26 Association validates equality but does not establish provenance. Coordinator34 distinguishes CausalReverseIo from Unsolicited, while the current wire carries causal request/lane/lease but no trusted proof of the thread that produced the callback. The original32 host must define how a callback on the active SDK-call thread receives that call's mapped Coordinator admission ordinal, and how a callback on another Miles thread is assigned a distinct unsolicited association. Merely seeing an active request must not label an unrelated background callback causal. Nor may a wire-provided scope/flag authorize cleanup. Proposed narrow policy for review: host call-thread TLS supplies causal context; callbacks with no such context are unsolicited; trusted client intake maps the authenticated session/request context to Coordinator IDs. Service validated causal and unsolicited file callbacks on the same FIFO engine worker in Active and Draining, retaining callback pins; Failed records observations but dispatches no new engine work. This needs parent acceptance and a concrete host-side association mapper before claiming operational callback routing. It requires no new generic scheduler, but cannot be replaced by a readiness placeholder.

**Next source patch after review.** One owner header/cpp plus the narrow preallocated encoder overload and portable tests of reservation-before-submit, allocation/submit rejection before side effect, local-key-zero publication, exact reply-byte parity, stale/replay handling, close once/ACK retirement, and uncertain retention. Worker integration uses FileInvocationJob33 unchanged; portable tests use deterministic adapter seams and never run Audio or Thread. The copied file26 header must include the already-reviewed33 private undefined Binding assignment declaration. No arbitrary injected production lifecycle flags, fake registration or fake file handles. Native compilation and real-engine behavior remain separate gates.
