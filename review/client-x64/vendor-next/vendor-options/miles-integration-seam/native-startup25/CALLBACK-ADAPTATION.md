# Callback contract before implementation

This candidate retains the four operation-shaped file callback signatures already checked by `protocol-candidate/sdk-declarations.cpp`. On the actual Windows SDK, MSS_FILE is char, UINTa is pointer-sized, read counts are U32 and seek offsets/results are S32. Public local callback typedefs use char, uintptr_t, uint32_t and int32_t with the Windows callback calling convention; the native translation unit statically compares every typedef to the possessed 7.2a SDK. It passes them directly only when those assertions compile. No raw pointer or callback ID is serialized here.

`reverse-file-seam20/ClientAudioFileCallbacks.h` remains the canonical client-local engine service. It is not itself an SDK callback table. A future integration thunk may translate its OpenResult/LocalFileHandle to these exact SDK-shaped callbacks, preserving open status separately from the valid zero handle. This candidate does not install that service or implement a second engine callback layer. The sample receives an existing local callback table; it never supplies fake successful file operations.

Calling convention is explicit __stdcall on Windows compiler targets and ordinary C++ for portable declaration checking only. Native checks require real v120 x64, where the original SDK and facade convention must compare equal. No x86 compatibility is claimed. Callback thread/TLS ownership, serialization, recursion, exceptions and shutdown quiescence are inherited integration obligations, not established by type compatibility. No callback is executed in the portable or planned native compile checks.
