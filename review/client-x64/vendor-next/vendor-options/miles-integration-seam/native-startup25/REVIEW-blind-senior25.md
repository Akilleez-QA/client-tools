## Substantive findings

1. **The direct native mappings are correct within the inspected x64 surface.** Callback registration, three listener operations, rolloff, serve, room query and room setter call the corresponding SDK operation with the expected arguments. Callback open status remains distinct from its pointer-sized output handle; read counts and seek offset/result widths match. The four callback-type assertions and exact scalar assertions are meaningful checks against the actual possessed SDK. The opaque driver cast reverses the cast used by native24 open; this works under the stated same-implementation lifetime convention, but provides no runtime ownership validation. The code correctly avoids claiming whole-facade ABI identity.

2. **The excerpt follows the actual successful-path SDK order.** Audio.cpp:1285–1373 initializes the redist path, starts Miles without branching on its return, registers callbacks, queries the mixer limit, opens the configured driver with stereo fallback, alters the listener, sets rolloff, reads speaker configuration, and eventually sets preference 42 to 16 then serves. SoundObject3d.cpp:28–34 supplies position, zero velocity and orientation in that order. The hardcoded 22050/16 matches Audio.cpp:2475–2488. The absence of an install-time SDK room setter is correct: Audio.cpp:3784 gates it on s_installed, which is still false. A startup return check or automatic shutdown inserted here would change the observed policy.

3. **The incomplete policy surface is disclosed accurately.** Mixer range rejection, logging, provider-string mutation, disable/remove behavior, file hook/timer setup and music-table work remain absent. The real failure path invokes remove while s_installed is false; shutdown is gated at Audio.cpp:1421–1437. Not inventing a shutdown in this excerpt is appropriate, but the omission is not evidence that partial-startup teardown is safe. The final native result explicitly excludes install-policy equivalence, and that limitation must remain attached to downstream use.

4. **Callback compatibility does not settle callback lifetime.** Existing Audio callbacks use engine file maps and per-thread initialization; type equality cannot establish thread ownership, reentrancy, callback quiescence or exception behavior. CALLBACK-ADAPTATION.md correctly leaves these unresolved. Registering raw callbacks here is reasonable for the native slice; any temporary pipe implementation still needs process-local thunks, separate success/handle representation (including valid zero), buffer copying and lifetime/teardown rules. These are future adoption blockers, not defects that require expanding this source-only patch.

## Small actionable improvements, not acceptance blockers

- **Sample fallback value is unconstrained.** sample/install_order.cpp:14 uses in.stereoProvider, whereas product Audio selects the actual fixed stereo value. Document that Inputs.stereoProvider must equal the possessed SDK stereo specification, or make that constant explicit in a subsequent revision. Current parameterization supports an order illustration, not policy equivalence for arbitrary Inputs.
- **Observation reuse can preserve old branch evidence.** sample/install_order.cpp:3 does not clear usedStereoFallback, firstOpenError, secondOpenError or speakerSpec. A fresh native lifetime does not require a fresh Observations instance. After a previous fallback, a successful first open can leave usedStereoFallback true; after a failed attempt, stale speaker data can survive. State that the output object must be freshly constructed for each call, or reset it before work. This affects the sample's evidence interpretation if it becomes executable, not today's compile result.
- **Fail closed on missing include discovery.** build-native.py:52–58 accepts equal empty include sets. The supplied logs/receipt include headers, so this does not invalidate the recorded run, but a changed localization/parser could weaken a future receipt silently. Require a nonempty set containing the expected SDK header before claiming header identity coverage. The portable checker records its explicit source list and compiler, not a complete transitive standard-header/toolchain closure; preserve that narrower claim.
