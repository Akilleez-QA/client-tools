# Portable registry85 — prospective gate, not run

Actual frozen83 ResourceRegistry and its actual unchanged protocol header are copied byte-identically under tree. No fake registry, SDK or production substitute. Local stack-object addresses serve only as opaque registry identities; no vendor operation, engine object or invalid numeric pointer is used.83's separate authored test is not executed or counted here.85 is the proposed six-group strict gate with its own frozen oracle/runner.

The test exercises only public methods of the actual header. The unpublished-handle probe uses the known next fresh slot, and subsequent publish must return exactly that same handle: this prevents a vacuous rejection of an unrelated guessed handle. No private-field exposure is used. Each negative operation checks its relevant output semantics; resolve must clear its output, failed publish/insert must preserve the sentinel handle. These are concrete lifecycle tests, not assertion-count padding:

1. Stream reservation refuses null, wrong-kind and closing driver; pending reservation cannot resolve/close/retire; null publish preserves the reservation and output; successful publication returns the exact previously probed identity. Parentless insert(Stream) refuses.
2. Borrowed insertion preserves the same identity for same parent/local; retarget refuses without changing output. Alias cannot independently close/retire. Stream beginClose blocks both stream and alias resolution, and retire/reuse advances both generations; old alias cannot select the replacement.
3. Driver retirement invalidates live owned/stream rows, closing stream rows, aliases and both unpublished child kinds. Failed stale publications preserve output. Unrelated File, second Driver and its owned sample survive. Refilling exactly eight freed slots then refusing the next insertion verifies actual cascade reclamation, not only parent-based lookup rejection.
4. Both explicit cancel and destructor on an invalidated old reservation are tested AFTER the same slot has been reused for a new pending stream generation. New publication must still succeed; old publish must not.
5. A pending reservation consumes capacity before publish; excess reservation and borrowed insertion refuse with unchanged output. Publishing the already reserved row still succeeds. Cancel permits reservation reuse without inventing a vendor side effect.
6. File generations1→2→exhausted never wrap; old handles cannot resolve or retire the replacement. Driver/stream/alias cascade at maximum generation exhausts the whole bounded registry. Exhaustion refuses future reserve/insert.

Every Reservation dies before its registry; the registry owns no identity object memory. No allocator fault, forced address reuse, SDK close, Session destructor or engine workload occurs. The test does not establish that Backend calls these methods in the right order; that is separately source-reviewed and needs its actual native gate. It also does not establish callback quiescence or allocator-free behavior by instrumentation.
