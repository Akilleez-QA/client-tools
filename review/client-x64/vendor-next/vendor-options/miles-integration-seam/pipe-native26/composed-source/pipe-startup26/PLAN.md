# Pipe startup 26: seven non-callback operations

Scope: source/portable-scripted spike only. Fit the private pipe implementation to native-startup25's listener position/velocity/orientation, rolloff, serve, room query and room setter. No product adoption, new wire IDs, SDK emulation, vendor execution or native run is authorized. Frozen startup23/backend24/native25 files are read-only inputs; all changes apply only to an isolated staged copy.

## Three independent review patches

1. `01-seven-pipe-operations.patch` changes only staged ClientMilesPipe.cpp, startup23 reply.h and backend.h. It implements seven existing public facade operations with existing protocol opcodes. Local driver identity is compared with the selected session's owned identity before dereference; running state is checked. Floats use memcpy to preserve F32 bits. Room input is encoded as unsigned 32-bit bits and signed output uses the existing signedValue conversion. Serve remains a separate targetless call. Existing terminal-failure handling/no-auto-replay is inherited unchanged. The decoder's only new return-value allowance is successful room_type. The host adds an explicit seven-op whitelist after startup/before shutdown and delegates to existing MilesHost::dispatch; its four status values are explicitly mapped. No file callback mapping or declaration is removed, and no callback implementation is supplied.
2. `02-fresh-sample-fixed-stereo.patch` independently resets install-order Observations before each attempt, removes caller-controlled stereo fallback input, adds a fixed local stereo constant and asserts it against actual MSS_MC_STEREO in the native source. This is an excerpt-state correction, not a new Audio policy. The original frozen sample remains unchanged.
3. `03-require-sdk-include-evidence.patch` independently makes the future native25 build driver reject empty include discovery or discovery without the expected actual Mss.h. It changes no compile flags or runtime scope. This patched driver is not invoked by the portable checks.

CALLBACK LIMIT: ClientMiles::set_file_callbacks has no pipe definition. The native facade still declares it; attempting to link a pipe caller fails. The test-only sample double is explicitly guarded by PIPE26_TEST_ONLY and never linked into the pipe mapping test or production source. No fake successful callback registration is provided by the pipe adapter.

## Portable evidence and deliberate limits

`check-portable.py` recursively stages quoted local includes for a bounded input list, records input hashes, applies all patches with zero fuzz, and compiles/runs authored scripted test executables with ASan/UBSan. It executes neither vendor nor native Windows code. Tests encode AND decode request frames with existing codecs and decode replies through the actual staged reply decoder. Seven mappings cover exact operation order, negative zero/negative finite/zero/positive infinity/quiet-NaN payload/subnormal float representations, signed -1/INT_MIN/zero room results and inputs, null/foreign driver rejection without channel access, pre-start/post-shutdown refusal, known refusal distinct from valid results, malformed field/correlation replies, and channel exceptions that prevent all later calls/replays.

The existing 202-check backend24 scripted test runs against the staged overlay to check compatibility of the reply change. The independent sample test verifies fixed stereo fallback and clearing stale prior observations when the next attempt faults immediately. A negative link check must fail specifically for missing ClientMiles::set_file_callbacks. None of those doubles establish vendor behavior for unusual float/room inputs; the tests establish that the adapter preserves the requested bits instead of deciding policy.

Before freezing, v2 added malformed-field failures and existing-startup regression checks; v1 evidence remains preserved. V2 passed 1267 seven-operation checks, 202 existing-startup checks, the sample correction test, and expected callback link failure. The host source addition is reviewed reuse, NOT an executed/compiled host claim in this gate. A later authorized native object check must include host-candidate/host_dispatch.cpp along with the staged backend; frozen startup23's old link source list does not automatically include that translation unit. Its exact 23-request FixtureOracle is intentionally not altered and is not a runnable controller for this new sequence. Do not run the old fixture and call the new seven operations validated. No change to admission/lane policy is made; old callback/thread/reentrancy gates remain open, including serve's possible vendor work.
