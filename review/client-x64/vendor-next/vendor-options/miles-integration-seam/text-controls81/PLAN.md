# Text-controls81 — two text methods, version explicitly unresolved

Source-only four-file overlay against77. Public70 header and every host/protocol implementation stay unchanged. This implements last_error and set_redist_directory through actual existing Core OwnedText requests and their real host SDK metadata dispatch, adding two guarded public definitions (52 total when composed with77 alone). It is independent of callback80. No test, compiler, VM, SDK/engine runtime, Git or product action has been performed.

## Existing native and paired semantics

Possessed Mss.h declares both actual functions as returning char pointers; set_redist takes a const input pointer. The selected public70 boundary deliberately promises adapter-owned const snapshots, distinguishes genuine null from nonnull empty, and guarantees each pointer until that SAME function's next call or completed shutdown. It does not promise shared vendor storage identity. Exact direct70 implementation already uses separate private snapshots and retains each directory input before its vendor call.

The existing pipe Core's last_errorOwned requires running state; directory setter permits pre-startup with requireAvailable. Actual Backend metadata gate matches those phases and forbids post-shutdown requests. Actual host metadata dispatch retains a copied directory in its SessionInputs list BEFORE invoking AIL_set_redist_directory, copies the actual returned bytes/null marker into an owned reply, and keeps retained input storage for its existing lifetime. No SDK-pointer identity or callback address crosses the pipe.81 reuses this route and does not fabricate text on refusal/failure or broaden lifecycle semantics outside it.

## Storage and bounds

Two separate std::string fields belong to the EXISTING Session, not a new global singleton or registry. Session construction precedes vendor calls. Each new private method obtains the corresponding complete validated OwnedText, then swaps it into its own field and returns that field's c_str or actual null. Empty nonnull yields c_str(), never null. The other function's storage is untouched. Publication occurs after decode, request/owner validation, returned/ACK join and owned-text reconstruction; any prior failure follows the existing terminal public guard. No caller output buffer is written.

Directory scanning now stops at RequestTextLimit rather than unbounded strlen: a terminator at the last permitted byte is accepted with its NUL included; no terminator within the limit fails before request/send/vendor work. Null input still fails. This is an extent bound on the existing valid readable C-string precondition, not a pointer probe or a guarantee for invalid memory. Wire output text already has the existing host copyText and decoder length/terminator/null-mask bounds. Over-limit response or retained-input budget failure remains an explicit refusal/private fatal path, never empty text.

Caller must serialize text access and all Session command access;81 supplies no lock, thread-local storage or new concurrency guarantee. A consumer using a returned pointer across a same-function call violates the explicit public lifetime. Calling the OTHER text function does not invalidate it. Passing a prior returned pointer as a later setter input remains safe within valid serialized use: request encoding copies before the later snapshot swap. Callback reentry is rejected by the existing public/Core guard before mutation.

The current Session is retained and normal destruction terminates. Its snapshots consequently remain allocated beyond the current shutdown request; the public guarantee ends no later than completed shutdown, but retaining storage longer does not require the caller to keep using it.81 adds no destructor cleanup, worker drain or successful paired-close claim. Future normal Session destruction can release these strings along with the existing owner after lifecycle proof. Host retained directory inputs are not released or replaced by81, including after uncertain outcomes.

## Why MSS_version is not implemented here

Root explicitly chose to leave this unresolved after inspecting the mismatch. Public70 accepts a writable positive capacity and direct70 invokes the actual selected Windows macro without adding a nonempty condition. Existing pipe SessionVersion instead carries no capacity, uses a fixed256-byte array, queries the retained module directly, rejects a zero LoadStringA result and maps it to VersionQueryFailed. Exposing MSS_versionOwned via a256-only wrapper or truncating/copying its result would silently invent semantics for arbitrary positive capacities, empty results and writes. A separate paired version patch must resolve these facts;81 changes neither that route nor the public contract.
