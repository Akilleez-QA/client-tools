## Actionable finding

**[P2] State and enforce unique basename ownership before treating the macro as a query of `currentDll`.** `session_version_host.cpp:12` checks `GetModuleHandleA(MSSDLLNAME)==currentDll`, then line 17 invokes the SDK macro, whose private Windows body calls `LoadLibrary(MSSDLLNAME)` again. The header contract requires a verified held module and exclusion of concurrent unload, but does not exclude another mapped DLL with the same basename. Microsoft documents unspecified selection for GetModuleHandleA with duplicate basenames, versus selection of the first loaded matching module for LoadLibraryA. Consequently the equality check is not, by its documented contract, proof that the macro will query the supplied module in that admitted state. This is a source/specification contract gap, not a reproduced wrong-module observation.

The current probe starts with no matching module, loads one exact path, and checks that path; its recorded success remains valid for that restricted setup. The minimal correction is to make a single matching basename, stable loader context, and loader-owner coordination explicit host preconditions, then have the integrating owner enforce them. If the adapter itself must prove identity in a broader process, add an identity check aligned with the macro's loading operation and a discriminating duplicate-basename test using harmless test modules under separate authorization. Simply repeating GetModuleHandleA does not strengthen the guarantee. [GetModuleHandleA](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulehandlea), [LoadLibraryA](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibrarya).

No other correctness defect was found in the reviewed portable contract. The remaining live transport, session admission, and Audio failure-handling work is accurately excluded from this component, rather than a reason to demand unrelated changes here.

## What the evidence supports

**Actual semantic target.** The product caller at `Audio.cpp:2466` allocates `char version[256]`, invokes `AIL_MSS_version(version, sizeof(version))`, and constructs a string. The actual private `Mss.h:4286` Windows macro loads the named DLL, reads resource 1 into the bounded buffer, and releases its own reference. The host invokes that macro by name with the same 256-byte ANSI shape and excludes Win64 and UNICODE compilation. This is a runtime DLL-resource query, not the SDK's compile-time `MSS_VERSION` literal. The Linux header branch would be a different operation; portable tests do not exercise it as a Miles query. The checked private header SHA-256 is `966e1e81046851295079e9709f9f358286c823e4403ec6b0ca972b5059725e6e`.

The poison build is valuable: recorded compile arguments define `MSS_VERSION="SV21_COMPILE_TIME_POISON"`; both native configurations still report resource text `7.2a`. Unlike an ordinary equality test where both strings happen to match, this rejects substitution of that SDK macro constant. It does not alone reject a hardcoded `7.2a` implementation; source inspection supplies that discrimination. The direct LoadStringA oracle bypasses the macro wrapper but shares the resource/API mechanism, Windows environment, and DLL. The packet properly acknowledges this coupling.

**Ownership and consumer strictness.** `makeReply` bounds the search at 256, rejects a missing terminator, and serializes only through the first NUL. The codec builds its own vector and swaps on success. `copyReply` first checks the underlying frame, Reply/opcode, full routing context, unused result fields, span length, final NUL, and absence of interior NULs. Only then does it copy into the caller's fixed array. Thus no stack tail is serialized, empty text remains a representable value, failure preserves the destination, and all returned text bytes are owned. This is not a decoder returning a borrowed pointer. Header size/magic/version and canonical spans are enforced by the inspected frozen codec, not merely assumed by this review.

The suite exercises empty, maximum, unterminated, high-bit, truncated, malformed, context-mismatched, and unused-field cases. A fresh Linux x64 build with `g++ -std=c++11 -Wall -Wextra -Werror -fsanitize=address,undefined -fno-omit-frame-pointer` passed **600/600** checks without sanitizer diagnostics. That is a repeated execution of the existing portable oracle under another toolchain; it is not independent test design or Windows behavior validation. No claim of exhaustive malformed-frame coverage follows from the count.

**Attribution.** Present local files match their source-v2 manifest entries; every source-v2 archive member listed by the manifest matches its hash. The two revision4 helper files are packaged in the archive rather than at the sibling paths in this Linux checkout; an initial verification command encountered that layout and stopped before tests. Archive verification then completed without mismatch. Native receipt source identities shown in `source_before` match the corresponding local source identities. The receipt hash is `da0b0381f67667e030c909f32ae6e1a2fbfd368224de37a294278d24c3a90857`; the runtime-results hash is `12a3e2ce412c89f9a99632aedeb632158496563a645c1d9a075361cdfdd78c9b`.

All eight recorded builds report zero exit, unchanged before/after inputs, and no uncovered observed library paths. The reviewed host and poison command records use v120, `/W4 /WX`, and user32 without a Miles import library. All twelve recorded launches have zero exits and matching pre/post executable and DLL hashes. Logs record native x86 host checks 22/22, poison checks 23/23, wire checks 600/600, and native x64 file consumption 606/606 in both configurations. The consumer data path uses files, not a live pipe. These are inspected collected runtime records, not native runs performed by this reviewer, and hashes bind identities rather than independently corroborating behavior.

**No unintended API.** The component introduces functions in `MilesSessionVersion`, reuses the existing opcode/schema, and neither defines an AIL replacement nor pretends AIL_MSS_version is an exported function. Product Audio source remains an external reference, not integrated code. A failed copy still requires a deliberate policy before the actual caller constructs its std::string; the packet states this boundary.
