No additional scripted execution was necessary for the source conclusions below.

- `pairMask` emits 0, 1, 2, 3 or 7. Two null pointers yield 0, not alias mode. Exact-equal nonnull pointers yield 7. `validPairMask` rejects 4, 5, 6 and every bit outside the low three.
- Each of the four modified real-dispatch arms validates the mask before resource resolution and SDK invocation. `PairOutputs` supplies null, distinct locals, or the same local as appropriate. The SDK sees the original pair topology; its write order determines the shared local's final value. Both reply slots are read from that final shared local in alias mode. No assumed order is implemented by the helper.
- Both client copyout paths (sample milliseconds and shared float getter helper) check alias reply equality before any caller write. Unrequested nonzero slots are likewise rejected before copyout. Existing decoding validates the remaining reply shape, and channel/decode failures poison the session. Thus malformed alias replies leave caller storage unchanged and prevent another request. Ordinary validated refusals still leave outputs unchanged without asserting uncertain execution.
- `miles_wire.h` increments private protocol Version from 1 to 2. The shared codec's `headerCommon` requires exact Version for calls and results, so old-version wire frames are rejected rather than silently interpreted. This is a coordinated peer upgrade, not negotiation: both host and client must be rebuilt from the v2 composition. Direct C++ calls to the dispatcher are an internal boundary and do not themselves validate a frame version.
- Stream milliseconds gains correct host-side topology support, but no new pipe stream facade or backend admission is implemented by this patch. Do not count this as working end-to-end stream coverage.
