# Sample host29 prospective source gate

New overlay against exact pipe-live27 frozen composition; preserve all older files. Implement actual x86 Backend handling for allocate_sample_handle, sample_ms_position, end_sample and release_sample_handle. No named binding, rebind, playback, EOS, callbacks, stream aliases, engine, vendor execution or VM invocation. Existing host_dispatch handles query/end. Actual SDK calls handle allocation/release. Match native-sample27 source contract and sample-pipe29 response shapes.

Before vendor allocation, ResourceRegistry obtains a reusable slot via a noncopyable RAII Reservation. reserve(kind,parent,token) may allocate/throw before vendor work; OwnedSample requires a currently live Driver parent. Reserved entries never resolve. publish(token,local,out) is allocation-free with v120-compatible throw() and makes the pointer durably tracked before exposing the identity. A stack PendingSample owner exists before allocation; it receives the vendor result immediately and releases on exceptional publication failure. Valid publication transfers tracking to the registry; wrong/consumed tokens fail without mutating output. Null vendor allocation cancels its reservation without consuming a published generation. Tokens index entries rather than retaining pointers invalidated by vector growth. Registry must outlive its tokens; tokens must be consumed before parent close. This is a single dispatch-thread contract with no callbacks registered, not a reentrant allocator or callback-quiescence claim.

Apply reservation to existing driver opening too, removing its identical post-vendor tracking allocation. Resource capacity/bad_alloc fails closed before the vendor call (host knows no vendor work happened, but client sees channel uncertainty; no graceful memory-exhaustion equivalence is claimed), never fabricated as vendor null or metadata input-budget status. Current finite slot namespace remains; release reuses slots and increments generation. No new cumulative sample cap or pointer tombstone container. Natural generation exhaustion remains bounded and cannot wrap into a live old identity.

Owned samples resolve only while their parent driver resolves. Release validates shape/live owned identity, invokes actual SDK release, then retires tracking after confirmed return. End/query forward through the real dispatcher after lifecycle checks. Actual shutdown precedes driver retirement and invalidates all child sample identities. There is no implicit end before release or per-sample release inserted into shutdown policy. Reply allocation/transport failure after a published allocation leaves the handle tracked until actual shutdown; no automatic retry.
