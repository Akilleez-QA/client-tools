## What is actually missing and smallest file-level integration

1. Public ClientMilesPipe.cpp needs the two guarded typed definitions; PipeCore.h/.cpp need their real operations. Attach typed callback registration state to existing sample/stream rows or one narrowly scoped session owner: separate SampleCallback/StreamCallback storage, registration ID, resource generation, previous pointer and lifetime pin. Allocate/retain before sending. Return the locally known previous pointer only after validated registration completion. The host's previous native pointer must agree with null/known installed thunk under exclusive ownership; an unknown foreign previous pointer cannot be translated or cast into a client callback. Callback code ownership currently lacks an EOS-specific pin contract; decide it at the private root, not by fabricating public arguments.
2. startup-bridge23/backend.h/paired-bootstrap59/host.cpp need actual typed registration transactions, exact request/reply rules and native thunk binding to existing resource identity. A small private EOS owner adjacent to host-runtime50 is plausible, but must use existing registry/session IDs rather than a second handle system. Producer callbacks must obtain a stable generation/registration record and enqueue a bounded retained event without allowing dispatch-thread registry races. Do not reserve vendor user-data slots implicitly. A delayed native callback supplies only HSAMPLE/HSTREAM: looking up a current row cannot distinguish an old registration selected before replacement or a recycled address. Registration replacement/null policy is a required decision before promising native prior-return semantics.
3. client-runtime53/client_file_runtime.cpp:138–143 currently forwards every callback-channel frame to the file mapper and accepts only FileQueued/AckConsumed. Add explicit EOS dispatch before that file branch, using actual decodeEos, exact session/resource/registration/sequence validation and existing coordinator accounting. Sole Endpoint owner must enqueue delivery and send CallbackAck after actual completion, without calling arbitrary game code inline while holding the control slot/owner lock. Host callback-channel owner likewise must multiplex EOS events and their ACKs without a competing pipe reader/writer. A file-only registration must not be an implicit prerequisite for routing a structurally valid EOS event; current mapper creation depends on file prepare.
4. Delivery requires a concrete client thread policy. Reusing EngineFileWorker merely because it exists would silently choose file-worker scheduling/TLS and shared queue ordering for arbitrary EOS callbacks. A deferred main-thread tick changes observable timing. The next design must specify causal synchronous completion during an admitted command separately from unsolicited completion during game computation, and how either progresses while the main thread waits. The existing Coordinator callback kind CausalReverseIo is file-specific in name/intent; do not relabel EOS as file I/O without reviewing completion semantics. No generic nested dispatcher is required or authorized by these primitives.
5. Close/release barriers must be integrated into existing Backend lifetime and Core row removal, not appended afterward. Mark registration closing, retain each accepted event with exact identity, observe SDK return, drain/ACK the defined frontier, then retire only after the selected producer-termination condition is actually established. Coordinator accepts late observations and advances closeFrontier; seeing the current frontier ACKed alone cannot prove no future callback.83 closes/retires no-EOS stream identities and Core erases successful close/release rows; EOS enablement must revisit that boundary before any queued delivery can reference them. Permanent tombstones are not a substitute for a specified barrier.

## Actual Audio observers, locks and reentry

Product Audio.cpp:2878/2960/3072 installs callbacks before starting sample/stream. At:4730–4789 callbacks find exact native handle in the appropriate map, set PS_done and immediately invoke Sound2::endOfSample. Product Sound2d.cpp:845–874 sets end flag, increments loop, invokes optional game callback, then resets fade/time. Its comment explicitly forbids some Miles calls and defers release to next alter; it does not authorize arbitrary nested Miles operations. PlayerMusicManager.cpp:103–107 updates completion flag/timer immediately; :590 onward consumes it and clears other game completion callbacks. Public registration prior-pointer return is still required even if these call sites ignore it.

Audio.cpp:2320–2337 wraps queued startSample calls in Audio::lock/unLock; their definitions:4920–4928 directly call AIL_lock/unlock. Both public pipe exports remain missing. Coordinator already models lane-owned recursive lease acquisition/release, but53 Publish always uses Ordinary and lease0, and paired host similarly has no operational SDK lock lane. Two blind lock/unlock RPCs are insufficient: specify helper SDK owner-thread lock scope AND client EOS delivery exclusion/order during that scope, including callbacks needed to finish synchronous calls. Do not hold a client mutex while waiting for a callback requiring that mutex/thread. Ordinary registration code can be authored under a no-lock restricted prototype, but that does not support actual Audio's locked start sequence.

File callback-reentry47/invocation_guard.cpp marks the entire active file Scope violated if any public forward call is attempted, even if caught. Preserve it. Never invoke EOS game code on the active file callback stack or use its guard as an undocumented all-EOS prohibition. Conversely, absence of that Scope on an EOS delivery thread would permit every public call today; that is not proof such reentry is valid. Before delivery, define the supported EOS-origin operations (actual observed callbacks themselves make no direct AIL call, but game callbacks are extensible), fail unsupported reentry before request/proxy mutation, and make close/release from that context consistent with Audio's existing deferral. Keep the two callback contexts explicit and avoid arbitrary nested command dispatch.

## Next concrete step

Reuse coordinator registration/frontier and codec identity rules to author a typed registration transaction plus bounded event-admission state attached to existing rows, with exact previous-pointer ownership and restrictions written first. That source work can precede runtime. Do not expose a nominally complete EOS export until replacement/null selection, delivery thread/lock policy and producer-termination/close barrier are resolved or explicitly restricted and accepted. The existing generation/protocol prototypes reduce work, but they do not supply those missing semantics. Current private header/object evidence cannot promise a future Miles64 runtime's callback timing. No operational Audio streaming or callbackquiescence claim follows from this map.
