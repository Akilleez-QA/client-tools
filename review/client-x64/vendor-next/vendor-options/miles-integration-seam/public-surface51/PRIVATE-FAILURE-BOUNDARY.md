# Required private failure containment — proposal only

Plain public declarations do not contain C++ exceptions by themselves. No existing object gate establishes this boundary and no termination path was executed.

The composition root privately supplies one engine fatal/report callback before the first public call, including calls that precede startup such as redist/version. Its argument shape is plain numeric reason plus `const char *` diagnostic text; no std::exception, std::string, ownership object or protocol frame crosses. The callback is not declared in candidate/ClientMiles.h, is not an application plugin API, and is not an extra argument on any game call. The composition retains its code and context through all adapter calls and callback quiescence. Once active, it is not hot-swapped.

The private binding can be expressed as a callback type `void (*)(uint32_t reason, const char *message)` in a composition-only header. Diagnostic text is a synchronous borrowed view: the engine callback must consume/copy it immediately in its own runtime and may not retain the pointer. The engine-owned function performs its existing fatal/report action. The private adapter does not assume this callback successfully terminates: if it is missing, returns, or throws, the adapter invokes a guaranteed nonreturning abort fallback. A C++ catch-all encloses invocation of the engine callback itself. The fallback does not allocate and does not throw.

Every game-facing function must wrap its **whole private operation**, including text snapshot creation, directory retention, result conversion, private state checks and post-call bookkeeping. Catch private typed exceptions only inside the private runtime; catch all remaining C++ exceptions there as well. Feed genuine faults into the private failure routine. There is no path that catches a bridge/allocator/protocol fault and returns a fabricated native zero, null, false, empty text, EOF or default metadata. Marking a declaration noexcept or changing its include files is not a substitute for this implementation.

Actual SDK return values remain untouched as values. For example, startup returning zero, driver/sample/stream allocation returning null, file open returning status zero, metadata returning zero, and the version macro writing an empty result on its native module-load-failure branch are not automatically adapter faults. A failure to validate or communicate a purported result is a different outcome and cannot be converted into one of those values. Unknown effects after a native or bridge call are terminal; no automatic retry or rollback is authorized.

Private native callback thunks need the matching catch boundary: exceptions from private bookkeeping or from invocation of the registered game callback cannot unwind through the vendor callback ABI. A catch-all must route them to the same nonreturning fault path. This does not justify catching and continuing after arbitrary structured exceptions, corrupted memory or OS faults; no SEH recovery policy is proposed. Callback35's direct pointer-forwarding implementation does not itself install such a thunk, so either its registered engine callbacks already satisfy a separately established no-unwind contract or the selected integration must supply reviewed containment without silently changing callback identity/lifetime semantics.

The public surface makes no recoverable exception promise. If existing standalone fixture code catches ClientMiles::Failure, that fixture interface must move private or be revised; the engine cannot retain that dependency merely to preserve old prototype tests. A later source/compile review must check all exit paths, callback entrypoints and the actual engine-bound reporter. Separate authorized runtime evidence would be needed for behavioral claims; this proposal authorizes none.
