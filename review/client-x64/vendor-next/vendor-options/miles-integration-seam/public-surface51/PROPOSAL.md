The returned-text lifetime is an **explicit proposed adapter guarantee**, not a discovered vendor guarantee: each of the first two functions owns its own reusable private snapshot. A pointer remains valid until the next invocation of that same function or completed shutdown, whichever comes first. The caller copies before then; it never frees or writes the pointer. No per-call permanent archive, arbitrary text cap or game-facing release handle is required. Reentrant/concurrent consumers must obey that invalidation rule; this proposal does not claim new thread-safety for them. Actual Audio copies redist text immediately and uses error text immediately in diagnostics. Retention is a private implementation task, not satisfied by declaring const char*.

The supplied SDK header declares char-pointer returns but does not specify a durable lifetime at those declarations. Thus forwarding its pointer and asserting shutdown lifetime would be unsupported. Conversely, the existing native24 implementation's private copyText already copies native text, so retaining a private snapshot is a concrete adaptation rather than an inference about vendor ownership. Copy/allocation failure must enter the private failure boundary, not return null or empty as a fabricated SDK result. Snapshot replacement should complete before discarding its predecessor; input-directory retention must be prepared before the vendor setter can retain it.

Version semantics are different from text retention. The possessed Windows macro performs a module resource query and writes caller storage; on its module-load-failure branch it writes an empty string. It does not provide a scalar success status. This proposal does not reproduce its implementation, promise a nonempty result, or assert a complete NUL-termination guarantee for every other resource-failure case. The native wrapper must preserve the macro's actual writes and not silently add the old native24 nonempty check (`backend-boundary24/native/native_miles64.cpp:82–88`). Any extra validation/initialization needed to address actual Audio's uninitialized local buffer must be a separately explicit behavior decision, not disguised as native equivalence. The chosen positive int32 capacity is an authored wrapper constraint matching Audio's256 and the Windows resource-call extent; macros have no exact C++ function-pointer signature to match.

The previous pipe version-query helper rejects some empty/error results. It cannot automatically satisfy this new public macro-shaped contract by replacing OwnedText with a c_str(). Its private result distinction and copy/extent behavior require explicit review if that implementation is later selected. That issue stays private and does not introduce a wire status or session handle in the game header.

## Required private changes; none implemented here

1. Move the old FailureReason/Failure and OwnedText implementation machinery into private headers. Catch modern-library exceptions before they cross engine TUs. Every public game call must contain its complete private work inside a catch boundary; no adapter-private exception may escape. A genuine adapter/bridge fault invokes a **private composition-supplied engine fatal/report callback**, synchronously with plain numeric/text data. If that callback is absent, returns, or throws, a nonreturning abort fallback runs. This is a proposed boundary, not one established by existing headers. See PRIVATE-FAILURE-BOUNDARY.md for its precise obligations. It is bound privately before startup, not selected by the game through a plugin API or a fifth per-call argument. Legitimate vendor zero/null/empty results remain ordinary values and must never enter this fault path merely for being zero/null/empty. No process termination has been executed.
2. Update the privately selected startup implementation to the text contracts above. Engine-owned std::string copies are constructed/destroyed in the engine TU. Private retained strings and directory storage are constructed/destroyed in their private runtime. No mixed-library owning object is returned by value. Keep existing startup/fallback/shutdown policy in Audio, without inserting extra startup-result branching or automatic shutdown.
3. Point native sample/playback/stream/private implementations at this consolidated plain declaration header and preserve common Sample identity. Preserve full intptr_t preferences, all driver channel choices and actual signed/unsigned arguments. Temporary pipe range restrictions are not common native restrictions.
4. Add private delegates for set_sample_file, scalar queries, lock/unlock, memory metadata and completion registration. Validate their actual selected SDK signatures and constants privately before any later compile gate. Pointer-based input images remain caller-retained under the existing vendor lifetime; this header does not introduce memory transfers.
5. File callbacks keep the exact callback35 typedef shapes and may use the already reviewed direct native registration. EOS/stream callback parameters use facade HSAMPLE/HSTREAM, deliberately distinct from SDK pointer types. Therefore a facade callback is **not** type-identical to AILSAMPLECB/AILSTREAMCB merely because both pointers have the same width. Supply actual AILCALLBACK native thunks that convert the opaque handle and invoke the retained facade callback, or another independently proven typed arrangement; do not reinterpret_cast function pointers. The facade registration return preserves the previous facade callback, matching the native API's previous-callback shape (SDK4706–4708 and5190). Native callbacks registered outside that mapping are not silently convertible. Correct previous-registration mapping, publication before any synchronous callback and callback-state lifetime remain private implementation requirements, not solved code in this proposal. Current Audio ignores returned previous callbacks but relies on callback identity at4730/4751/4772.
6. Implement WAV_info using a private real SDK structure and field-by-field projection into SampleInformation only after nonzero native success. The private SDK's format/bits/channels are signed32 and data length/rate/samples/block size unsigned32 (declaration1748–1759). Audio uses exactly these fields at3714–3726. The output projection deliberately omits data/initial pointers and channel-mask fields unused by this caller; it is not a wire-format struct. Failure leaves the projected output unchanged, which is a stated facade rule rather than a claim about untouched vendor output bytes.
7. Replace actual engine include/type/constant usages only in a future reviewed adoption change. FirstClientAudio.h currently includes mss.h. The candidate defines only used preference, speaker, sample-state, file-type/error and environment constants. Their numerical mappings were inspected in the private header; future private static assertions must prevent drift. This proposal supplies no compiled proof of those assertions and copies no SDK implementation bodies.
