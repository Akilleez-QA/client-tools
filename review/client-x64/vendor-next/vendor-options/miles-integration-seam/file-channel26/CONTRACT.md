# Private source contract

`file_channel.h` is the complete proposed boundary. It adds no public game-facing API. `FileServices` is only a table of the exact four seam20 local signatures; canonicalServices takes those existing function addresses. The real wrappers remain external unresolved symbols in this spike's compile-only object.

Receive-side code can call decodeRequest; it owns copied filename bytes and invokes no file service. The trusted connection/coordinator must supply the expected association and establish session/replay validity. FileOpen uses text only, Close uses target only, Seek uses target/value0 signed bits/value1 origin, Read uses target/value0 U32 count. All other fields are zero. Reply uses return_bits, an open-success File identity, and read bytes only. These assignments are a private authored mapping of the existing abstract contract, not a modification or claim of prior coverage by the frozen generic codec.

Invocation copies validated input, pins an externally owned Binding for non-open calls and retains the supplied execution-context storage. The caller must already have admitted it onto an engine-compatible executor. `invokeOnAdmittedExecutor` is an explicit synchronous entry with that precondition; it is never called from decoding, teardown, a reactor hook or an implicit worker. A duplicate entry makes no second call. No automatic close or file deletion occurs. The original canonical callbacks retain native ownership.

The begun/returned flags are ordinary bools. Duplicate-entry prevention therefore applies only within one serialized admitted executor; this class is not safe for simultaneous invocations. CallThrew means a side effect may already have happened. It permits neither replay nor file retirement and cannot be encoded as ordinary native failure. The existing external file owner must preserve uncertain ownership; this spike deliberately does not supply that unresolved policy. Returned failed-open key bits remain available for diagnosis but are never published as a live file.

Completion preserves raw return bits. A successful open with local key0 is valid, but encodeCompletion requires a separate nonnull published wire File identity. This spike does not decide how that owner reserves capacity, publishes or rolls back an open. Read owns exactly actual returned bytes when actual<=request and actual<=staging; an out-of-range value is retained as ReadCountOutsideBuffer, never ordinary EOF. Seek keeps its original signed32 bits. copyRead checks count and destination span before any write.

The production-blocking boundary is exact: nothing in current seam20/coordinator source establishes the engine executor/TLS route or file cleanup after an uncertain disconnected open/close. Therefore this candidate does not install callbacks, deliver a real reverse channel, create a production file registry or claim cancellation releases files. Tests use a scripted executor and existing Coordinator callback pins to distinguish queued cancellation, running cancellation, observed return and late acknowledgement. Those schedules validate mechanisms only.
