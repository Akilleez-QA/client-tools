## Observations and research

Input identities are captured in input-identities.json. Canonical seam20 has four ordinary synchronous C++ calls: OpenResult open(char const*), void close(LocalFileHandle), int32_t seek(LocalFileHandle,int32_t,uint32_t), uint32_t read(LocalFileHandle,void*,uint32_t). LocalFileHandle wraps uintptr_t; open status is independent and zero is a valid successful local handle. Only the original callbacks own the actual file map/deletion. Original Audio.cpp casts signed read return to U32; an out-of-range unsigned result cannot become ordinary EOF. Seek returns tell(), including negative bits, rather than the ignored seek boolean.

The existing wire schema contains FileOpen/Close/Seek/Read and reverse envelopes, but no operation-specific file validator. Coordinator-candidate separates observed return from semantic success, retains pending callback pins in Failed, and acknowledges only explicit callback completion. Its independent oracle requires exact association, no duplicate execution, separate acknowledgement and execution, and no guessed callback executor. The original TreeFile path buffer is512 bytes; this spike supports at most511 filename bytes plus NUL, without normalization. Read support is bounded by signed32 and the one-frame payload limit; larger transfers are explicitly unsupported.

Research retrieved2026-09-30: [Microsoft CancelIoEx](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex) separates cancellation request from observed completion and forbids early storage reuse. This supports retaining an execution pin, not an engine cancellation guarantee. [C++ shared ownership](https://eel.is/c++draft/util.smartptr.shared) distinguishes object lifetime from synchronization of the object; shared ownership does not establish engine thread safety. [RAD history](https://www.radgametools.com/msshist.htm) records callback/platform changes; it does not prove this old build's worker affinity. The possessed source and header remain authoritative for this narrow signature contract. No external source supplies the missing engine route.

Topology: framed reverse values → strict validation → owned operation storage → externally admitted/pinned local binding → exactly one canonical call → bounded scalar/byte completion → validated reverse result. Two unresolved transitions are deliberately not supplied: selecting a real initialized executor, and resolving live-file ownership after uncertain disconnect/publication. A scripted executor is a test sensor, not evidence of either.

## Contract and prospective checks

The private FileServices table uses the exact seam20 function signatures, and canonical_services.cpp only takes the addresses of those four declared calls. Compile that adapter to an object; do not link the actual engine wrappers. Tests use an explicitly test-only table. No public game API or new generic filesystem is added.

decodeRequest(frame, expected association, out) accepts only a complete reverse file request, exact request/causal/lane/lease association, known field meanings and no unused payload/fields. It copies filename bytes. A failed decode preserves out. Connection/session and replay/cancel decisions remain external admission inputs; no untrusted frame manufactures authority. Result conversion owns read bytes; open status and local handle remain separate until a trusted owner supplies a published File identity. A successful open with no publication identity cannot be encoded. A failed open publishes none. Seek preserves signed32 bits. Read actual0 is successful EOF; actual greater than requested records raw callback bits as an explicit unrepresentable result, with no byte copy or successful wire reply. Close carries no invented scalar success.

The private invocation object retains request, local binding and supplied lifetime pin while a synchronous service call runs. It makes no callbacks from decode or destruction and performs no automatic close. Repeated invocation is rejected. Caller supplies an already-admitted executor context; this source does not construct that context or choose threads. Test executor keeps a running invocation alive through cancel/late completion, uses Coordinator callback pins until actual return, rejects duplicate/stale/cancelled queued work and does not claim engine safety.

Tests will cover open status0 versus successful handle0 and a high uintptr_t handle; signed negative seek offset/result; short read, EOF and raw out-of-range failure; malformed spans, field masks, filename extents/embedded NUL, count limits and reply mismatch; owned bytes after source overwrite; no service call on intake/rejection; duplicate invocation; queued cancellation versus running cancellation with retained storage/pins; late/stale/duplicate completion rejection. Finite scripted order is the oracle, not a latency or scheduling guarantee.

Success: portable warnings-as-errors build plus ASan/UBSan scripted checks pass with source/compiler identities before/after; canonical service adapter compiles to an object with unresolved real seam symbols. Any failure is retained before repair. No VM or vendor execution follows automatically. The highest possible claim is correct value mapping and modeled pin behavior under an externally supplied executor contract. Engine routing, file publication/rollback/disconnect ownership, real callbacks and whole-client fidelity remain open.
