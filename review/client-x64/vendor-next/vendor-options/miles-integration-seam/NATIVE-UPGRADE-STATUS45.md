# Native-shaped Miles interface: callback connection checkpoint

The client-facing functions remain shaped like a direct Miles x64 integration. Direct SDK adapters use the possessed Win64 declarations and leave the actual SDK imports unresolved. The temporary pipe implements the same declarations privately. No x64 Miles library is available here; none has been fabricated or replaced by a success stub.

The replacement seam is a source interface, not a claim that arbitrary newer Miles versions are binary-compatible. A future native adapter can replace the pipe implementation, its host process and its private protocol while preserving these callers. Vendor assets and SDK header bodies remain private.

## File path progress

- **Owner37:** 189 portable checks for file ownership, preallocation, publication, uncertain siblings and consumption ACKs. Executor behavior was scripted.
- **Native owner dependencies:** owner39 compiled after removing one redundant typename; native41 compiled the other five actual v120 AMD64 objects. The job references the real engine worker, but this snapshot still selects canonical services. No runtime occurred.
- **Selected callbacks44:** 316 portable checks exercise the actual retained-table adapter and Invocation/codec. Non-1 open statuses, zero/wide local handles, signed seeks, exact selected-table dispatch, exceptions and lifetime retention passed. The owner/job source now accepts these services, but that new plumbing has not yet been executed or compiled natively.
- **Control owner45:** 11 portable scenarios (155 assertions) exercise the real mapper/owner/coordinator with a scripted worker. Forward completion and causal consumption ACKs join without blocking the control thread. Ordinary calls only; lock actions are deliberately excluded until their result semantics are connected.

The next candidate combines44 and45, with actual worker/job compilation and a continuous reverse-pipe owner to follow. Host installation remains disabled until this path is complete. The existing sample host's idle watchdog and callback rejection are fixture behavior and cannot be copied into an operational audio session.

## Preserved failures and limits

Native38 failed on VS2013 syntax. Native39 compiled its owner but its symbol checker read demangled trailing text rather than the symbol name; the raw log positively identifies that checker error. Native40 stopped before compilation because the launcher could not import its staged parser. Native41 used the corrected parser and launcher, retained the earlier records, and reused rather than rebuilt the native39 owner. These are separate observations, not one six-object clean first run.

Operational callback registration, exact ACK wire schema, continuous idle I/O, worker lifetime/teardown, sample input-buffer retirement, callback floating-point state and measured playback fidelity remain open. Original-DLL identity does not prove that a separate host preserves all timing or floating-point behavior. The rejected engine/allocator workload was not repeated.
