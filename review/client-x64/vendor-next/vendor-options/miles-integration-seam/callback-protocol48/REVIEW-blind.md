# Blind source review — callback-protocol48

Reviewed source.patch and the actual candidate file_protocol, codec, schema and relevant file-channel definitions, then compared the stream success contract with the existing private StartupBridge reply decoder and ClientMilesPipe stream_sample_handle implementation. This is source inspection only. No build, test, VM, vendor, engine or endpoint was run; only this report was written. No operational SDK or product49d0 change is implied.

**No concrete blocking field-validation, correlation, fail-closed, or API-drift defect found in this candidate.** It is suitable to proceed to the proposed bounded portable gate, without treating source inspection as a test result.

The install request accepts only the exact no-payload shape with nonzero registration and the admitted ordinary origin. Success and refusal replies have intentionally different registration rules; the success echo compares against retained request state, while refusals require zero. Every Result field is accounted for, including exact byte length, scalar return, handle, values, spans, null mask and callback. Unknown statuses fail instead of becoming a normal refusal. The allowed status numbers agree with the existing private status enum. Nothing relaxes the existing generic reply decoder's callback-zero rule.

The consumption ACK preserves the original request/cause/lane/lease and compares both original file opcode and registration with retained expectations. It rejects EOS CallbackAck and file-request opcodes as ACK envelopes. Its callback field is not interpreted as a peer-selected intake ordinal. The generic codec checks version, magic, total length, reserved value, handle validity and canonical span layout; the typed validator supplies the remaining opcode-specific restrictions. Exact 136-byte length plus empty spans disallows extra payload. FileAckExpected is public and forgeable by trusted local code, so its independent capture and retention remain API preconditions; this is not an untrusted-wire bypass in the validator itself.

The bounded Call encoder performs all rejection checks before creating FixedWriter and shares field serialization with the vector encoder. It writes explicit little-endian fields, normalizes total bytes/spans just like the existing vector path, and introduces no allocation in the bounded path. No rejected path writes buffer or written. The documented non-aliasing and valid-buffer preconditions still apply. Header.bytes from a retained expectation is not itself treated as correlation identity; encoding recomputes it and decoding enforces the actual frame length, which is appropriate here.

The stream helper matches the existing combined reply-decoder and stream_sample_handle success rules: status zero, null or valid BorrowedSample, no unrelated result fields, exact retained Stream kind/slot/generation echo even when alias is null. Its apparent lack of explicit nonzero alias slot/generation checks is not a hole: decodeResult already calls validHandle. Stable repeated alias identity and cross-parent reuse checks correctly remain with the stream owner and are not silently claimed by this standalone success helper.

Private version3 rejects earlier headers through the common codec. FileConsumptionAck is appended after the unchanged EOS ACK and SessionClose values. The bounded encoder is additive, and the vector encoder's factored field sequence is unchanged. I found no public ClientMiles signature change or unnecessary new state framework. The narrow separate install decoder is justified by its success-echo rule. The standalone stream helper duplicates a small success shape intentionally; later integration should use it consistently rather than maintaining competing v3 checks.

Before claiming executable validation, the proposed gate should particularly retain its independent golden-byte oracle, per-field mutations, nonzero generic payload comparison of vector/bounded Call encoding, unchanged-output sentinels, invalid partial BorrowedSample handles, and old-version rejection across every codec entry point. Round trips alone could share the same serialization error. Stateless duplicate ACK validation must remain distinct from one-time mapper consumption. SDK installation, authenticated session provenance, ACK transport direction/dispatch, and correct capture of expected fields are external composition obligations, not missing behavior of this source-only codec.
