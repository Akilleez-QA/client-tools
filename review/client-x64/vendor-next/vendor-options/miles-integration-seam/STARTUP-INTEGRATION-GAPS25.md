## What backend-boundary24 currently does

`ClientMiles.h` exposes eight startup/metadata operations plus a narrow speaker-spec query: startup/shutdown, preference get/set, owned last-error/redist/version, driver open and speaker spec. `native/native_miles64.cpp` forwards to the actual SDK and inspects declarations. `pipe/ClientMilesPipe.cpp` implements private wire mapping and a separate `Failure` path.

`sample/startup_calls.cpp` is a fixture sequence: version query, two redist calls, startup-result early exit, several preference/error checks, one stereo open and shutdown. It is **not Audio::install**. The real install does not query version here, change the redist path to dot, test both 16/64 fragments before opening, or branch on the startup return. Copying this fixture into Audio would change ordering and policy.

The pipe currently accepts only 22050 Hz, 16-bit, stereo, zero flags and one successful driver. The real `getFrequency/getBits` at 2475–2488 do return 22050/16, but `getProviderSpec` at 912–934 supports system config, headphones, stereo, multiple discrete surround configurations and Dolby Surround. Rejecting those requests as facade errors before the SDK call would bypass Audio's existing vendor-null fallback path. Extend accepted source operations/host validation for the actual provider set; do not turn unsupported transport scope into a fake null driver or silently force stereo.

## Service and remove must be included before adoption

`Audio::serve:4943–4961` checks main thread, non-null device, a nonempty playing list and timer, then calls AIL_serve only after accumulated elapsed time exceeds 0.05 seconds. `Audio::alter` calls this wrapper at2448–2451. `src/external/ours/library/fileInterface/src/shared/AbstractFile.cpp:54–55` also invokes the registered callback before readEntireFileAndClose. Do not introduce a new polling thread, move game work onto a pipe reactor, or coalesce these calls.

Normal `Audio::remove:1380–1470` first calls setRoomType while installed, requiring **room_type and set_room_type** with the existing support check. It then stops all sounds, clears sample/stream maps and local purge state; stopAllSounds also stops buffered sound/music and calls Audio::alter(0). Thus full normal remove reaches existing playback release/end/close and service policy; startup-only shutdown is not a replacement for it. Only after these steps does remove set installed=false and zero the driver, call AIL_shutdown, inspect file handles and delete remaining cached bytes/timer. Preserve buffer/callback lifetime through shutdown completion.

Bink's normal default-priority ExitChain teardown precedes Audio's (see BINK-BINDING-REACHABILITY24.md). Keep original Bink consuming the real same-process driver through a private binding; never pass a facade/pipe proxy to it. No raw AIL call in Bink is needed for this dependency to be real. ### Partial startup and shutdown failure are open lifecycle decisions

The current second-driver-null branch calls `remove()` **before** `s_installed` is true. Its shutdown guard at1421 therefore skips AIL_shutdown even though startup was already attempted. Do not describe current cleanup as complete or silently change s_installed early to make it run: that would also enable room/playback paths during partial startup. An independent backend-started state or scoped startup owner can support confirmed-startup cleanup without changing Audio's normal fallback/scheduling decisions, but this is an explicit lifecycle correction requiring source review and targeted validation, not a mechanical rename.

Current pipe startup returning zero leaves started=false; `shutdown()` requires running and `Session::close()` requires stopped=true. The ordinary graceful close route therefore does not cover a confirmed failed startup. Abandonment currently falls to concrete-channel cleanup. Define that outcome separately; do not invoke vendor shutdown after failed startup without evidence it is allowed, and do not pretend normal SessionClose occurred.

If the pipe shutdown request throws or loses its reply, SDK outcome is unknown. The session marks channel failure terminal; no automatic replay is allowed. Audio currently sets installed=false and driver=null before its void SDK shutdown call. Substituting a throwing facade there can skip subsequent cache/timer cleanup and escape through ExitChain. Add an explicit integration-level catch/cleanup policy retaining local backing/context until host termination or quiescence is established, preserving the original failure and preventing another vendor shutdown attempt. Successful SDK shutdown and private channel close/drain remain separate; pipe teardown is not a new Audio policy operation. The native adapter has no SDK shutdown status return to invent.
