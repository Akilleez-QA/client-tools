# Client runtime53 — source composition, not an adopted session

This adds a private modern-runtime control owner, not a replacement public Session or game API. No compilation, tests, VM, SDK, engine or product execution occurred. No existing frozen source changed.

## Ownership and actual implementation

`Runtime::launch` takes a reference to a connected callback pipe handle already authenticated against the session by the outer root. No callback I/O may have occurred. Failure before thread creation leaves the handle with the caller; after successful thread creation it invalidates the caller's handle and retains the Runtime for process lifetime in this slice. The control thread alone constructs Endpoint and Coordinator and signals actual readiness. Endpoint constructor failure closes its transferred handle according to existing code; allocation failure before construction leaves raw ownership retained. There is no claim that an integer supplied here authenticates a peer.

The single command caller uses `publish` before command send. A synchronized single shared Ticket records ordinary command wire identity/lane/resource pins. The control thread mints the next local ordinal only after admission succeeds. Resources must already be checked against the actual forward registry. A mutex serializes posting; the ticket remains owned if an OS wait fails. Done publication synchronizes result visibility. Command waits also observe the terminal event; the outer command pipe loop must watch the borrowed `failureEvent()` and call `fail()` on command failure. No callback Endpoint access is allowed there after handoff.

Before file registration, ordinary startup/redist commands use the existing Coordinator directly. `returned` is legal only after actual fully validated forward reply, then completes and consumes local command state. `prepare` refuses any active command: pre-registration work must finish first. It retains the actual selected44/46 callback table, creates and starts the actual engine worker (waiting for its existing installed-TLS Started result), then creates owner and mapper on the same coordinator. Only successful preparation permits an outer installer to send opcode28. Preparing is not an SDK installation observation. No dummy canonical table or reset admission sequence is used.

After preparation, publication/return goes through dispatch50 mapper. A return Ticket can remain pending while the control loop continuously handles callbacks and ACKs. Once mapper state becomes Settled, the control owner consumes it and signals the command caller. Lock actions/leases are not exposed: this slice is ordinary, zero-lease only. Unsupported lock semantics must not be inferred from the old facade's separate lock entrypoints.

Every received callback frame goes to `receiveControl` from50. Its existing Reverse row retains expected ACK context and consumes it once. The only mapper extension is `nextUnqueuedReply`, a scan of existing rows, not another registry. The control owner polls actual jobs without waiting on the worker, copies ready replies into Endpoint and marks queued only on successful send acceptance. Endpoint send allocation can fail after file effects; that is terminal with retained ownership, never a fabricated callback result. The loop pumps every bounded idle tick even with no game command; no command-silence watchdog is added.

## Explicit failure and unfinished lifecycle

`fail` requests failure atomically and wakes the control owner; only the control owner marks Coordinator Failed or cancels/drains callback Endpoint. `terminal` signals failed control state to posted command waits and the outer command owner. File callback/ACK rejection, uncertain job, endpoint failure or an exception terminates normal intake. Partial preparation retains any started worker/context already published. Every file owner and its complete FileRecords remain retained, including successful open records with zero pending reverses.

There is deliberately no callable destructor, clean-stop result or normal worker join. On failure the control thread stays alive, polls cancellation completion and retains Endpoint storage, tickets, coordinator, mapper, file owner, selected callbacks, engine pin and worker. This is an explicit incomplete retained failed-session owner for later root composition, not acceptable final normal teardown and not a recovery design. The outer process-fatal policy is still required before any operational gate. Raw input-handle retention on pre-Endpoint allocation failure is also left with this retained runtime. Nothing silently discards it.

Actual SDK shutdown must occur while this runtime still pumps, followed by causal settlement. Host process death/producer quiescence and all-file-close proof are absent here; Coordinator's vendorTerminationUnproven remains unchanged. A future implementation must establish those facts before stopping callback intake, draining/joining the worker, draining Endpoint and releasing its context. This draft supplies none of those proof inputs and will not reinterpret zero callbacks as zero open files.

## Remaining concrete integration

- Wire this same Runtime into actual private Session/LiveChannel; remove all old command-thread callback Endpoint I/O. Hello stays outside SDK command admission. No old live fixture has been replaced here.
- Bind selected callbacks/code pin before installation send; validate protocol48 install reply separately; commit actual Installed only on its verified settled success. Known refusal versus uncertain installation remains the installer's decision. There is no runtime Installed boolean standing in for that observation.
- Use the existing47 public forward reentry guard before posting; this private component assumes its caller enforces that boundary. Calling a synchronous command post from the worker callback would deadlock and is not supported.
- Complete forward registry authority, lock/lease transitions, ordinary versus shutdown cleanup admission and the proven normal/failure lifecycle above before a paired operational claim.
- Audit/compile the Windows thread/event/mutex ownership paths. Current source has never been compiled; existing component receipts do not validate this thread composition. Selected EngineFileWorker implementation remains an external engine object behind its plain header; actual FileInvocationJob source is present and no portable substitution exists.
