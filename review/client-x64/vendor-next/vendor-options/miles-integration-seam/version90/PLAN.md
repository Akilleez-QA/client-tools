Public guarded void MSS_version forwards to Core with exact int32 capacity. Core rejects null/nonpositive as InvalidArgument and capacities above CapacityLimit as InputLimit before sending or writing. CapacityLimit is the existing1MiB reply budget minus128 bytes (1048448). Pre-startup access is allowed within the selected private session; existing stopped/session-unavailable restrictions remain.

Request SessionVersion value0 carries capacity; all other call fields are empty. The old zero-value fixed256 query is rejected. Successful replies carry bytes, not text: an actual written prefix including its final NUL, with all unrelated result fields zero. There is no packet status derived from LoadString's count. Generic reply decoding validates framing/context/status/budget/terminal byte and owns the bytes; Session::validateReply additionally verifies extent against the actual request capacity before LiveChannel's existing returned join. Core copies only that prefix afterward. Parent host.cpp re-encodes owned bytes rather than silently dropping them. Refusals cannot carry bytes. No caller tail is transmitted, initialized or overwritten.

Private host query validates the request, allocates initialized owned scratch before API entry, calls LoadLibraryA with the SDK-private DLL-name constant, and applies the selected low-module genuine-empty behavior. For a module, it calls LoadStringA(resource1, exactcapacity), captures count only to identify the write prefix and frees the acquired module through RAII. Count0 with a written NUL is normal. A negative/out-of-range count or missing terminator fails terminally as an unsupported private outcome, without fabricating output. The zero-count write behavior is backed by probe84's24 own-resource cases on Windows/ACP1252 only, not a universal Windows/codepage/vendor proof. A real library-load failure is one zero-byte prefix result, not VersionQueryFailed.
