MSVC x64 rejects the naked inline-assembly implementations of `htonl`, `ntohl`, `htons` and `ntohs`. Use the corresponding 32-bit and 16-bit byte-swap functions under `_M_X64`, preserving the Win32 implementation and public signatures. The production change is **one file, +26/-0**.

This package is stacked on the joint [helper PR37](https://github.com/SWG-Source/src/pull/37) and [workflow PR38](https://github.com/SWG-Source/src/pull/38) base `09932a32c9949bd40e8e4dbb22e1a7027944eb21`. The ByteOrder source repair itself applies to master: its baseline file is byte-identical. PR37 resolves the foundation header's x64 memory-move overload prerequisite; PR38 repairs inherited build CI. Neither changes byte-order semantics.

The original and patched production files are byte-identical to the corresponding client files. [Recorded client native/hosted leaf-function evidence](https://github.com/Akilleez-QA/client-tools/blob/94e606c9e4031622b0893314b3b1f738c3b82467/review/client-x64/pr-ready-next/byteorder/submission/RESULTS.md) covers 166,631 input cases in both directions per candidate configuration, original-source controls and deliberate no-swap controls. This supports the conversion implementation; **it is not an exact server native build result**. Server foundation headers differ, and the client runner assumes a different source/include layout.

This source-only package adds no test runner or CI. Local preparation verified the clean source cherry-pick, byte identities and whitespace checks; no new build or runtime test was run. Complete server Windows compilation, packet behavior and runtime acceptance are outside this evidence.
