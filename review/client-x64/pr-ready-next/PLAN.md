# Small-client candidate preparation

User frame: prepare small manageable test PR versions and improve them using blind Astra maintainer/senior-engineer reviews. No new PRs or upstream writes; authorized fork commits/pushes remain allowed. Existing PR22/23/24 remain untouched. Fidelity is a product acceptance constraint, not proved by these finite library tests. Context is explicit enough to waive a redundant question.

Research gate already consulted on 2026-09-30: Google Engineering Practices small-CL guidance https://google.github.io/eng-practices/review/developer/small-cls.html and GitHub base/head reference https://docs.github.com/en/pull-requests/reference/branches. Queries concerned independently buildable small changes, tests, and actual diff bases. These support scope/dependency discipline, not correctness of our patches. Actual compiler/tests and repository graph remain authoritative for this code.

20 materially distinct paths before convergence: (1) one full integration PR; (2) one commit per PR; (3) group by root cause; (4) group by library ownership; (5) group by compatibility boundary; (6) sequential stacked dependency PRs; (7) independent master-based branches; (8) prerequisite common-header PR first; (9) production and tests together; (10) tests-only reproducer first then production; (11) immutable external evidence with small source PR; (12) native hosted CI; (13) portable cross-compiler CI with native artifact supplement; (14) Windows maintainer reproduction package; (15) freeze source and independently reproduce historical results; (16) use negative controls to qualify test sensors; (17) adversarial senior-engineer review; (18) maintainer reviewability/merge review; (19) defer non-independent candidates and ship only self-contained ones; (20) consult upstream target/acceptance conventions before final submission.

Decision: three provisional root-cause branches on known master, tests packaged with source where possible, two independent role reviews, and fresh native checks. If fresh compilation identifies a prerequisite, record failed attempt and change sequencing explicitly; never suppress a header or substitute declarations merely to pass. No native full x64 product claim.

Prospective checks: actual ByteOrder TU with real repository headers on Win32/x64 Debug/Release, independent byte oracle and exact 166631 input count; real network-header include-order matrix with bounded UDP/IOCP API tests, no production TCP-runtime claim; PCRE actual provider correct-count cases with caller-binding validation and no execution of unsafe old count. Source and inputs hashed; fresh output directories; failures retained; no allocator-fault or real-engine teardown workloads. Stop a candidate's success claim on build/run mismatch, not the broader goal.

Blind review independence: two fresh fork-none Astra agents, distinct roles, same artifacts and model so not independent empirical corroboration. Initial reports exclude peer reports and earlier triage conclusions. Scores are assessments; tests establish bounded behavior. Version all feedback/revisions and preserve failed attempts.
